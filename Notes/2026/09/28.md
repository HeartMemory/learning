## 今日沉淀

### 一、委托：三个"不是魔法"的实证

| 问题 | 结论 | 怎么证的（可复现） |
|---|---|---|
| `Invoke` 我没写，哪来的？ | `delegate` 声明 = 请编译器**生成一个类**，`Invoke` 是那个类型**自带的成员** | 反射打印 `typeof(MathOp).GetMethod("Invoke")` → `Int32 Invoke(Int32, Int32)`；`Action<int>` / `Func<int,int,int>` 同样都有 `Invoke` |
| `x(30)` 和 `x.Invoke(30)` 什么关系 | **同一件事**，前者是简写（编译器翻译的） | 两种写法输出完全一致 |
| 委托实例里到底装了什么 | "哪个方法 + 挂在哪个对象上" | `op.Method` → `Int32 Add(Int32, Int32)`；`op.Target` → 空（静态方法没有目标对象）；多播 `chain.GetInvocationList().Length` → `2` |

### 二、多播的四条语义（会考）

1. `+=` 是**加**、`-=` 是**减**（不是"换"）
2. **链上每个方法都会执行，但只拿得到最后一个的返回值** → 多播 + 有返回值 = 用错了（`Action` 系无返回，天生适合广播）
3. `+=` / `-=` 底层是 **`Delegate.Combine/Remove` 生成新对象再赋回** → 减空之后变量**可以是 null**（编译器给 **CS8602** 警告的正是这件事）
4. `Invoke` 顺链执行 = `GetInvocationList()` 的天然遍历

### 三、两条硬边界

- **委托可以是 null** → 调用点写 `?.Invoke(...)`。判据：**通知类旁路**（可选）允许安静跳过；**接线类**（必须有人接）在**装配期响亮失败**（`Debug.LogError(..., this)` + `enabled = false`）
- **名义类型**：`Action<int,int>` / `Func<int,int,int>` / 自定义 `MathOp` **签名一样也不能互相赋值**（CS0029）→ 要显式 `new Func<int,int,int>(op)` 包一层（或 lambda 包，09-30 学）

### 四、Unity：装配期检查 vs 运行期检查

- **`Start`（一次）**：装配 `_notifyScore = scoreManager.SetDestroyedCount;` + 查"必须有人接"的接线
- **`Update`（每帧）**：只查每帧真的要读的状态源（`brickSpawner`）
- ⚠️ **委托不能序列化** → 永远不能在检查器里拖；想在面板上配就得换 **`UnityEvent`**（Unity 自己的可序列化类型，代价是更重）
- `[SerializeField] ScoreManager` **保留**：它是**装配插头**，不再出现在每帧路径上
