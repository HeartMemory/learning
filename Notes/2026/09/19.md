## 今日沉淀

### 算法：350 与 349 的分水岭
- **349 要"去重后的交集"** → HashSet 一句话解决；**350 要"带次数的交集"**（`[1,1,1] ∩ [1,1] = [1,1]`）→ HashSet 恰好把次数信息丢了
- **库存模型**（= 383 赎金信反过来用）：先给 nums1 建 `Dictionary<值, 剩余件数>`，扫 nums2 时"命中就取走一件、计数 −1"，减到 0 就取不动了 → **"取较小值"由机制自动实现**
- **顺手修掉的脏写入**：`dict[n2] = times - 1;` 放在条件外，会给 `nums2` 里独有的数字插入 `-1` 的垃圾记录，把空间从 `O(unique(nums1))` 撑大成 `O(unique(a)+unique(b))` → 改成 `if (TryGetValue(...) && times > 0) { Add; 计数-1; }`（**一次查表同时完成"查+判断"**）

### Prefab 与实例化（详见 [`Unity-基础笔记.md`](../Unity-基础笔记.md) 第 4 章）
- **模具 vs 副本**：改 Prefab 源文件 → 所有**未覆盖**的副本同步
- **`Instantiate` 内部三步**：反序列化（读模板文件）→ 装配（建组件、填 `[SerializeField]` 值、修引用）→ 入场景（触发 `Awake`/`OnEnable`，`Start` 等下一帧）
- **与 `new` 的分水岭**：`new GameObject()` = 空壳；`Instantiate` = 带整套组件与数值的副本，**成本高**（这就是对象池的动机）
- **`Quaternion.identity`** = 不旋转（identity ≈ 数字里的 1）；第三格是**覆盖**，会抹掉模板自带旋转
- **容器保持干净变换**：`位置(0,0,0)` + `旋转(0,0,0)` + `缩放(1,1,1)` → 本地坐标 = 世界坐标，算坐标的代码全部安全

### 父子变换：缩放容器会怎样（实验验证）
| 改 Board 的… | 子物体（砖块）的反应 |
|---|---|
| 位置 | 整体**平移**，形状与间距比例不变 ✅ |
| 旋转 | 整片砖墙**跟着转** |
| 缩放 `x=2` | 砖块世界尺寸 `1.6×0.6 → 3.2×0.6`（变宽变扁）、间距 `1.7 → 3.4`、碰撞体一起放大 |

- **检查器里显示的是本地值**（还是 1.6/0.6）→ 数据上看不出来，只有 Scene 视图能看出
- **连带隐患**：`localScale.x * 0.5f` 算半宽只在"无父物体 / 父缩放为 1"时成立，被缩放父物体包住就得用 `lossyScale` 或 `SpriteRenderer.bounds.extents`

### ⭐ 两起事故（今天的硬货）

**事故 1：字段初始化器里访问 `transform`**
```csharp
// ❌ 类成员位置（字段初始化器）—— Unity 直接拒绝
float halfPaddle = transform.localScale.x * 0.5f;
```
- 报错大意：`get_transform is not allowed to be called from a MonoBehaviour constructor (or instance field initializer)`
- **生命周期顺序**：`C# 构造函数（字段初始化器跑在这）` → `Awake`（从这里才有 `transform`/`GetComponent`/`Camera.main`）→ `OnEnable` → `Start`
- 修法：需要引擎信息的计算全搬进 `Awake`；**只有要跨方法用的结果才升成字段**（`_limit`），中间量用局部变量

**事故 2：生成器自引用 → 指数爆炸 → 编辑器假死**
- 症状：一进播放就卡死，Unity 无响应（Stop 点不动）
- 根因（从场景文件里挖出的**铁证**）：
  ```yaml
  --- !u!114 &1906376736                  # BrickSpawner 组件
    m_GameObject: {fileID: 1906376735}    # 挂在【场景里的 Brick】上
    brickPrefab: {fileID: 1906376735}     # ← 指向自己！
  ```
  → `Instantiate(self)` 的每个副本**也带着生成器** → 32 → 32² → 32³ … 💥
- **硬核判别法**：拖进槽位的引用，**带 `guid` = 指向 Assets 里的资产（对）**；**只有 `fileID` = 指向场景里的对象（错）**
- **救场流程**：任务管理器强杀 `Unity.exe`（播放模式改动不保存，场景不会坏）→ 重启后弹 **Recovering Scene Backups** 选「是」（未保存的编辑只在 `Assets/_Recovery/`）→ 检查修好 → `Ctrl+S` → 删掉 `_Recovery/`（别提交）

**事故 3（编辑器侧）：文件被"覆盖"清空**
- 新建的 `Notes/Unity-基础笔记.md` 一度只剩 3 字节（BOM），原因是编辑器里残留的旧标签页被保存/覆盖
- **对策（协作约定 ⑪ 的实证）**：AI 改完文件后，编辑器里的旧标签页**先关掉再重开**；遇到"文件内容较新"提示**永远先点"比较"，绝不点"覆盖"**

### 防御性编程：给自己装保险丝
```csharp
if (cols <= 0 || rows <= 0) return;
if (cols * rows > 200) { Debug.LogError($"数量异常：{cols} × {rows}，已拒绝生成"); return; }
Debug.Log($"准备生成 {cols * rows} 块砖");   // 先打印"打算做多少"，日志才能说明意图
```
原则：**对"外部输入"（检查器手输的值、别人拖进来的引用）先做合法性检查再动手。**

节律：**加物体 / 拖引用 → `Ctrl+S` 存场景 → 再播放**。（今天磁盘上的场景里没有 `Board`，就是这条没做到）
