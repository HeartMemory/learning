## 今日沉淀

### 一、UI 坐标是"第三套坐标系"

| 参考系 | 代码 | 检查器 |
|---|---|---|
| 世界 | `transform.position` | ❌ 看不到 |
| 本地（普通物体） | `transform.localPosition` | ✅「位置」 |
| **UI（RectTransform）** | **`rectTransform.anchoredPosition`** | ✅「位置 X / Y」← 相对**锚点**的**像素**偏移 |

**定位公式**：`世界位置 = Canvas + 锚点在父矩形中的位置 + anchoredPosition − 轴心影响`

**⭐ 锚点 vs 轴心（今天踩的坑）**：
- **锚点**决定"相对父容器的**哪个点**定位 + 父容器变化时怎么跟着变"（归一化 0~1）
- **轴心**决定"自身**哪一点**对准那个位置"
- 想"左上角贴边 40/30" → **锚点 (0,1) + 轴心 (0,1)** + 位置 (40,−30)；轴心留在默认 (0.5,0.5) 时，同一个数值会把**元素中心**放过去 → 400 宽的框一半在画布外 → **被切**

### 二、Canvas 三种渲染模式（选型判据）

| 模式 | UI 活在哪儿 | 用途 |
|---|---|---|
| **屏幕空间 - 叠加** | 直接贴屏幕，永远盖在画面上 | **HUD / 计分 / 血条** ← 本项目 |
| 屏幕空间 - 摄像机 | 挂在某台相机前，跟着相机走 | 需要被 3D 物体遮挡 / 后处理 |
| 世界空间 | 世界里的一个平面 | 游戏内面板 / 告示牌 / VR UI |

⚠️ 叠加模式下 Canvas 的 `LocalScale = (0,0,0)` / `sizeDelta = (0,0)` 是**引擎驱动的占位值**，别去动它。

### 三、Canvas Scaler 三件套 + "参考分辨率 = 设计稿基准"

| 字段 | 结论 |
|---|---|
| UI 缩放模式 | `常量像素大小`（画布 = 屏幕像素数，小窗口挤爆）→ **改用「按屏幕大小缩放」** |
| **参考分辨率** | **= 美术设计稿尺寸**（1920×1080 主流基准）。⚠️ **不是"我的屏幕多大"**：800×600 → 1920×1080 后，同一字号观感**直接砍半**（缩放系数从 ~2.08 变 1.0） |
| 屏幕匹配模式 | `Match Width Or Height`（推荐）／ `展开`（取较小缩放系数 → **绝不裁切**）／ `Shrink`（取较大者 → **可能裁掉**） |
| 匹配（Match） | 0 = 保左右，1 = 保上下，**0.5 = 折中** |
| 每单位像素参考 | 只管**精灵/图片**的原生尺寸换算，**与文字无关**，默认 100 不要动 |

**"UI 会不会被压缩变形？"——不会。** 缩放系数是**单一标量**（等比），UI 只整体放大缩小；**只有"超出画布矩形"的部分不渲染**（= 被切）。

### 四、TextMeshPro（TMP）

- **来源**：包 `com.unity.ugui`（`Packages/manifest.json`）｜程序集 `Unity.TextMeshPro`｜命名空间 **`TMPro`**
- **资产**：`Assets/TextMesh Pro/`（导入"TMP 基础资源"生成）——**必须进 git**（含 `.meta`）
- **两件事分开**：`using TMPro;` 管**代码里的类型名**；`Assets/TextMesh Pro/` 管**字体/Shader/设置资产**
- **类型谱系**：`TMP_Text`（**抽象基类**）→ `TextMeshProUGUI`（UI）/ `TextMeshPro`（3D）→ 字段用基类更通用（09-15 抽象类的实战价值）
- **中文坑**：默认字体 `LiberationSans SDF` **无中文字形** → 中文变方块 + 控制台警告；三条路：只放数字/英文（今天）／建 Dynamic 中文字体资产／加 Fallback List。⚠️ 系统字体不可随项目分发，商业项目要用开源字体

### 五、UI 的性能纪律（与对象池同源）

1. **重建由"数据变化"决定，不由"代码每帧执行"决定**（`text` 的 setter 有脏检查，值相同直接 return）
2. **但每帧执行仍有代价**：`_score.ToString()` 每次都在堆上新建字符串 → **GC 垃圾**
3. `Auto Size` 不要开；**自动布局组件**会把"改文字"升级成"重新排布"（最贵）
4. **纪律**：**写 UI 由"数据变化"触发，不由 `Update` 触发**
5. 验证工具：Profiler 看 `GC Alloc` + `Canvas.SendWillRenderCanvases`

> 与昨天串起来：**对象池**把"分配次数"压成常数（对付 GC），**UI 纪律**把"重建次数"压成常数（对付 Canvas 重算）—— 同一个思想：**把频繁发生的昂贵操作，改成只在必要时发生**。

### 六、坑清单（今天遇到的）

| 现象 | 原因 |
|---|---|
| UI **什么都不显示** | TMP 的**文本内容为空**（`m_text:` 空）—— 内容比样式更先要检查 |
| 文字**被切一截** | **轴心在中心**（默认 0.5,0.5）+ 偏移小于自身一半 → 一半在画布外 |
| 改参考分辨率后**字变小** | 基准被放大 → 同一字号数值相对变小 → **按新基准重定数值** |
| 分数**加了两次**的风险 | 加分若写在防线之前 → 重复归还也会加分（今天放对了位置） |
