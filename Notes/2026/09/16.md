## 今日沉淀

**哈希线收尾（算法）**
- **判环两种路线**：① HashSet 登记（哈希线正题，`Add` 返回值一步完成"查+登记"）；② 快慢指针（141 的原班人马，把"平方和"当 next 指针）
- **387 两趟结构**：第一趟收集信息（计数）、第二趟做判断（找首个 1）—— 和 202 的"先登记再变换"是同一个思维：**信息不全时不做结论**
- **`int[26]` vs `Dictionary` 决策树**：约束稳定 + 值域小 → 数组（特化哈希表，连哈希函数都省）；值域可能变（大写/中文/Unicode）→ Dictionary

**Unity 生命周期（主线，详见基础笔记第 25 章）**
- 顺序：`Awake → OnEnable → Start → (每帧 Update → LateUpdate) → OnDisable → OnDestroy`
- **一生一次**：`Awake`、`Start`、`OnDestroy`；**每次进出都触发**：`OnEnable`、`OnDisable`
- **`Update` 一秒跑了一千多次**（编辑器没开垂直同步）→ **帧率不是常数** → 所有速度逻辑必须 `* Time.deltaTime`（帧率无关性铁律）
- **`LateUpdate` 存在的理由**：多组件 `Update` 顺序不保证 → 相机跟随必须放 `LateUpdate`，否则拿到的是上一帧位置 → 画面抖动

**⭐ 组件禁用 vs 物体禁用（实测洞察）**
- 取消**组件**勾选 → 只影响这一个组件；取消**物体**勾选（`SetActive`）→ 物体上所有组件 + **子物体全部失活**
- **但从脚本自身看，两种情况收到的回调一模一样（`OnDisable`/`OnEnable`）**——脚本分不清"我被禁用"还是"我所在物体被禁用"，区别只在**影响范围**
- 天然对照实验：一个物体上挂了两个相同的 `BattleDemo`，勾选的跑完整战斗，**未勾选的一条日志都没有**

**两个工程坑**
- **编码**：脚本含中文/emoji → VS 弹「Unicode 保存」→ **必须点"是"存 UTF-8**（Unity 按 UTF-8 解析 `.cs`）
- **粘贴括号层级**：忘闭合 `Start()` → 后面的类型声明被吸进方法体 → `CS1513` + `CS1022`。教训：**看见"括号类报错"先数括号，别盯代码内容**

**场景心智模型（今天最后一课）**
- **你运行的不是"某个脚本"，而是"整个场景"**：播放时场景里所有物体**同时活着、同时运行**（`LifecycleTester` 的 `① Awake` 就是这么冒出来的）
- 场景保存（`Ctrl+S` 存 `.unity`）和代码保存（VS 的 `Ctrl+S`）是**两件独立的事**

**接口回收（追问整理）**
- `IEnumerable<T>` / `IList<T>` / `IDictionary<K,V>` 和自写的 `IAttackable` **是同一个东西**，区别只在"谁写的 + **消费者是谁**"
- 你其实早就写过 `IList<IList<int>>`（118 杨辉三角）和 `IReadOnlyList<string>`（09-08 封装），只是没意识到它叫什么
- **铁律：接口必须有"另一端"才有意义** —— `IAttackable` 的另一端是你写的 `Attack()`，`IEnumerable<T>` 的另一端是 **`foreach` 关键字本身**
- `KeyValuePair<K,V>` 确实没用过（从没遍历过 Dictionary），如实记录

**`using` 的机制**
- `using X;` 不是"引入"，只是**把 X 里的类型名加进检索范围**（短名 → 全名的查找表）；类型全名永远是 `UnityEngine.Debug`
- **万能判定法：删掉这个 `using`，编译一次，看哪儿报红。** 不报红 = 没用

**计基随行（消息机制 vs vtable）**
- `virtual/override`：编译器决定，查 vtable，**错了编译报错**
- Unity 生命周期：引擎按**名字**点名，结果缓存成"消息表"，**错了静默失效**
- 为什么 Unity 选点名：`private` 也能被调用、不依赖继承、多语言兼容、想用哪个写哪个 —— **代价是没有编译期保护**
