## 今日沉淀

**哈希表（算法 + 计基随行）**
- `HashSet<T>.Add(x)` 返回 bool：**加进去返回 true，已存在返回 false**——一次调用同时完成"查 + 登记"
- `Dictionary<K,V>` 设计方法论：**"按什么查"决定"什么当 key"**（要按数字查下标 → 数字是 key、下标是 value）
- **先查后存**：否则一个元素会和自己配对（`ContainsKey`/`TryGetValue` 在前，赋值在后）
- `TryGetValue` vs `ContainsKey` + `dict[k]`：前者一次哈希查找（同时回答"在不在"+"值是多少"），后者要查两遍
- 底层原理：buckets（桶，存索引）+ entries（条目：HashCode/Next/Value）；**质数表长取模**避免"只用到哈希低位"；冲突用链地址法；满了扩容 rehash；先比 HashCode 再比 Equals（便宜的比较先做）
- `Entry` 是内部私有 struct（值类型、连续内存、无对象头）——**实现细节，面试问到"数组+链地址法、质数取模、先哈希后 Equals"就到头了**

**接口 interface（OOP 收官）**
- **契约本质**：编译器逐条核对实现类是否有匹配成员（名字 + 参数 + 返回类型 + public），缺一条报 **CS0535**
- **裁剪视角**：变量声明类型决定你能看到谁——`TreasureChest` 变量能看到 `IsOpened`，`IAttackable` 变量只能看到契约三条
- **契约随血缘下传**：父类实现了接口，所有子孙自动也是（Hero/Monster 没写 `: IAttackable` 却能用）
- **继承成员也算"找到"**：Character 加接口时一个成员都没改（祖传的成员恰好对上）
- 形态要求：接口要属性就不能用字段顶（`public string Name;` 字段 → 报错）
- **接口 vs 继承**：is-a（是一种）vs can-do（能做）；单继承 vs 多实现；复用代码 vs 解耦依赖
- **"面向接口编程"的实感**：`Attack(IAttackable)` 一行未改就能攻击宝箱——**调用方只依赖"能力"，不依赖"身份"**

**out 参数机制**
- 本质是**传变量的地址**（方法往你的坑位里写），所以能"带出来"
- 不要求初始化（方法负责赋值，且必须在所有路径赋值）；返回前不能读取
- 找不到时的约定值：Try 系 API 会赋默认值（int → 0），但因为返回 false，调用方不会用到
- 记忆：**`out` 是"递空碗出去接"，`new` 是"自己捏一个碗"**——方向相反
