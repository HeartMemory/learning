## 今日沉淀

### 一、算法：219 的模型与那行"多余的保险丝"

**正确模型（一句话）**：遍历时对每个数字查"它上次在哪"，差值 ≤ k 就返回 true；**不管有没有命中，都把当前位置覆盖登记**——因为和 i 差值最小的那次，一定是**最近**一次。"

**踩的坑（已写进错题本第 10 条）**：

```csharp
if (nums.Length < k) return false;   // ❌ 把"数组短"当成"没答案"
```

- **反例**：`[1,1], k=5` → 两个 1 相距 1 ≤ 5，**答案是真**，这行却提前返回 `false`
- **为什么 7 组用例全绿**：我的短数组用例（`[1], k=1`、`[], k=5`）期望**本来就是 false** → **错误原因给出了正确答案**，等于没测
- **修法**：`nums.Length < 2`（"一对至少需要两个元素"才是真不变量），或直接删（循环从 `i = 0` 起，空数组天然安全）

**📌 与 09-20 的对照（今天最有价值的一句）**：205 的"先查后登记"用的是**幂等写**（值相同再写一遍无害，省掉 `else`）；219 的登记**必须覆盖写**（留下最早下标就是假 AC）。**同一个骨架，"登记语义"由需求决定**——先问"我要的是第一次、最后一次、还是仅存在性"。

### 二、Unity：今天真正确立的知识块（详见 [`Unity-基础笔记.md`](../Unity-基础笔记.md) 第 5 章）

| 主题 | 一句话结论 |
|---|---|
| **物理材质与混合规则** | 弹性/摩擦是**成对算**的：反弹合并默认不是"取最大值"→ 墙不挂材质时球越弹越矮。本项目的取值：**摩擦 0 / 弹性 1 / 反弹合并 = 最大 / 摩擦组合 = 平均（隐患：墙默认摩擦 0.4 → 混合出 0.2）** |
| **材质挂哪儿** | **挂在 Collider 上**（一具刚体可以有多个 Collider、各挂各的，"冰鞋"模型）；刚体级那个槽是 Unity 6 的便捷入口，本项目**留空**——权威在碰撞体 |
| **Collider vs Rigidbody** | Collider 决定"**能不能被撞到**"，Rigidbody 决定"**位置归不归物理引擎管**"；双方都无刚体 → 静态×静态，**不产生任何回调** |
| **三种主体类型** | Dynamic 受物理驱动、会被撞飞；Kinematic 由代码驱动、**不会被撞动但能推动别人**；Static 谁都不动最省性能。**Kinematic × Static 不产生回调**（挡板贴墙没有事件，限位只能靠 `Clamp`） |
| **球的配置** | Dynamic + 重力缩放 0（俯视图无重力）+ 碰撞检测**持续**（防高速穿墙）+ 阻尼归零；休眠模式设"从不休眠"，避免慢速时"睡着卡住" |
| **发球 API** | Unity 6 里 `velocity` 已废弃 → **`linearVelocity`**；方向必须 `normalized`（否则斜向速度变成 1.414 倍） |
| **`OnCollisionEnter2D(Collision2D other)`** | 引擎"按名字点名"的回调（拼错即静默失效）；`other.gameObject` 是对方物体、`_rb.linearVelocity` 是**撞后**的自己的速度；`Enter/Stay/Exit` 三兄弟；触发器回调参数是 `Collider2D`（无接触数据） |

### 三、我讲错、被你用事实纠正的一处（记一笔）

我说 `Where(x => ...)` 你"已经用过"——**核实后是错的**：仓库里 `=>` 的 6 次出现全是**表达式主体成员**（`public static int TotalCount => _totalCount;`），那是语法糖；而 Lambda 是**匿名方法 + 委托对象**，属于 Block 3 才登场的内容。**这是我第二次被你抓错，两次都是靠"去代码里核对"而不是靠感觉**——这个习惯比知识点值钱。
