## 今日沉淀

**成品 5 号设计**
- 攻击骨架（不 virtual，流程锁死）：宣告 → `target.TakeDamage(CalcDamage())`
- 伤害钩子（`protected virtual int CalcDamage()`）：默认返回 AttackPower，Hero 改写为 `base.CalcDamage() + 加成`
- **多态的汇演**：`foreach (Character c in heroes) c.Attack(enemy)`——声明类型全是 Character，剑士出剑技、法师出法技、怪物老实平A

**null 与契约（今天最值钱的一课）**
- **隐式契约**：三处代码“同时看同一个元素”才成立（HasAlive 看最后一个 + FindFirstAlive 兜底返回最后一个）——改一处，闭环断裂（NRE 实证）
- **显式契约**：`null` 明确表示“没有”，不依赖任何隐含前提，调用方判断即可
- 原则：**错误要用数据本身表达**（null/异常/空集合），不要靠“别处的实现恰好配合”
- `Character?` 可空标注：把“可能为空”写进类型 → 编译器替你在每个调用点站岗（CS8603 警告消失 = 承诺与实现一致）

**控制流层级（return vs break）**
- `break` 只跳出当前这一层循环 → 流程继续往下（循环外收尾能执行）
- `return` 直接终结整个方法 → 循环外一切代码永远不会执行
- 判断标准：结束“这一轮/这一队”用 break；结束“整个流程”（参数非法等卫语句场景）用 return
- **防护归防护、决策归决策**：循环内判空只 `break`（局部防护），胜负判定放循环外**唯一一处**（DRY）

**重构的代价与手法**
- 改结构要重走所有路径：胜负宣告曾“寄生”在循环内的判空上，判空改成纯防护后，宣告就丢了
- `HasAlive` 一行重构：`=> FindFirstAlive(team) != null`——消灭重复逻辑 + 消除“只看最后一个”的隐式前提 + 避免空队伍越界
- 设计判断：**数值差异用数据参数**（能跑通即可），**行为差异才用子类**；“数据做计算输入 ✅”与“数据做分支条件 ❌”性质不同
