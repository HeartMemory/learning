## 今日沉淀

### 一、三种遍历对照（满树 `[1,2,3,4,5,6,7]`，今天实测）

| 遍历 | 顺序 | 结果 | 题号 |
|---|---|---|---|
| 前序 | 根 → 左 → 右 | `1,2,4,5,3,6,7` | 144（09-28） |
| 中序 | 左 → 根 → 右 | `4,2,5,1,6,3,7` | 94（09-29） |
| 后序 | 左 → 右 → 根 | `4,5,2,6,7,3,1` | **145（今天）** |

- 代码层面：**只有"把 `node.val` 装进结果"那一行的位置不同**，递归方法其余部分逐字相同。
- 形状判据（今天 12 组用例实测）：
  - **两条斜链在后序里都是倒序**（全左 `1→2→3→4`、全右 `1→2→3→4` 后序都得 `4,3,2,1`）——⚠️ 与中序不同（中序是"全左倒序 / 全右正序"）；
  - 教训：**别用中序的直觉去猜后序**，形状判据必须逐条实测。
- 用途判据：**后序天生适合"自底向上"的问题** —— 求树高 / 算子树大小 / 释放资源（先处理完孩子，才轮到自己）。

### 二、Lambda 的四种形态（今天全跑了一遍）

| 形态 | 写法 | 说明 |
|---|---|---|
| 表达式 lambda | `x => x * 2` | 一句能算完，**省略 `return`** |
| 语句 lambda | `(a,b) => { int s = a + b; return s; }` | 多行要花括号 + 显式 `return` |
| 无参 lambda | `() => Console.WriteLine("hi")` | 直接装进 `Action` |
| 匿名方法（了解级） | `delegate (int x) { return x * 3; }` | **C# 2.0 的前身**；与 lambda 最终都编译成**委托实例**，所以能互换 |

⚠️ **lambda 自己没有类型**：`var f = x => x + 1;` 编译不过 —— 必须靠**目标类型**推断（`Func<int,int> g = x => x + 1;` / 当参数传 / `return` 到已知返回类型）。

### 三、⭐ 闭包 = 变量被搬进"显示类"（今天最硬的一节）

实测输出（练习 ③ 段）：

```text
lambda 的方法声明类型 = Program+<>c__DisplayClass0_0
这个隐藏类里的字段：
  Int32 counter = 2
  Int32 shared  = 0
```

三条推论（都能解释前面学过的现象）：

1. **被捕获的局部变量不再住在栈上** —— 它成了**堆上某个对象的字段** → **生命周期被延长**（这就是 09-29「退订实验」里"主流程早就丢掉 `temp`，它却还收到通知"的底层原因）。
2. **同一作用域里被捕获的变量住进同一个显示类**（`counter` 与 `shared` 同框）→ 它们由**同一个对象的两个字段**承载。
3. **`bump.Target` 就是这个显示类实例**（不再是"你写的那个对象"）→ 直接解释了 09-29 那条"**现写的 lambda 退不掉**"：每次现写都是**新的显示类实例 + 新的方法**，`-=` 自然找不到它。

### 四、两个经典坑（实测数字）

| 坑 | 现象 | 原因（两条缺一不可） | 修法 |
|---|---|---|---|
| **`for` 捕获** | 攒起来再调用 → 三行都是 `3` | ① `for` 的 `i` 声明在**循环头** → 全程只有**一个**变量（一个箱子）；② lambda **调用时才读** | 循环体内 `int copy = i;` → 打印 `0 / 1 / 2` |
| **捕获的是变量不是值** | `inc()` 两次后 `show()` 打出 `2` | 两个 lambda 看到的是**同一个字段** `shared` | 想"定格当时的值" → 先把值存进一个局部变量再捕获 |

**反证实验（今天真跑过）**：同一个 `i`，若在循环体里**立刻调用**，打印 `0 1 2` —— 变量照样共享，只是**读得早**。
→ 判据：**"3 3 3" = 变量共享 ＋ 延迟读，两个条件同时成立**（`foreach` 是 `A B C`，属 C# 5 起的语言规定：**迭代变量每轮新建**）。

### 五、别混淆：`=>` 表达式主体成员 vs lambda（销 09-21 的回访项）

```csharp
public int Double(int x) => x * 2;        // 表达式主体成员 → 编译成一个【普通方法】（没有委托对象）
Func<int,int> f = x => x * 2;             // lambda            → 编译成一个【委托实例】（背后可能还有显示类）
```

- 判据：**看 `=>` 左边是不是"方法签名"** —— 是（`public int Double(int x)`）→ 只是**语法糖**；不是（变量 / 参数位）→ 是**委托**，会生成对象。
- 同一个箭头符号，两种完全不同的产物 —— 09-21 记的那条回访项在这里销掉。

### 六、连带回答：事件 + lambda 的落地判据

- 退订的唯一条件：**同一方法实例**（`Method` + `Target` 都相同）；**现写的 lambda 每次都是新对象 → 退不掉**。
- ✅ **Unity 判据：要用 lambda 订阅，就必须先把它存进字段**。
- ✅ 因此今天**主动不做**"Breakout 用 lambda 重写事件订阅"：`FailZone.BallLost += OnBallLost;`（方法组）换成 `+= () => OnBallLost()`，**语义等价但退订会失效**（`OnDestroy` 里的 `-=` 退不掉 → 悬空引用 → `MissingReferenceException`，**`?.` 也防不住**）。**保持 09-29 的方法组形态才是正解** —— 这一项的产出不是代码，是判据。
