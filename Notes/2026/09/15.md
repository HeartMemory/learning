## 今日沉淀

**哈希表（算法）**
- **计数消耗模式**：一份"资源清单"（magazine 字符数）→ 逐个消耗 → 不够就失败
- **`TryGetValue` 默认值 0 的活用**：`if (times == 0) return false;` 一行同时拦截"字符不存在"和"配额用完"两种情况（数值上都是 0）
- **HashSet 集合运算**：`IntersectWith` / `UnionWith` / `ExceptWith` —— **原地修改、返回 void**（对比 LINQ 的 `OrderBy` 返回新集合）
- `new HashSet<int>(nums)` 直接吃数组并自动去重（一行完成"装 + 去重"）
- **无序性实证**：同一组数据，手动版输出 `[9,4]`、集合运算版输出 `[4,9]`——遍历顺序由内部桶布局决定，所以题目才允许"顺序不限"

**抽象类 abstract（主线）**
- `abstract class` → 不能 `new`（CS0144）；`abstract 成员` → 子类**必须** override（CS0534）
- `abstract` 成员只能住在 `abstract` 类里（图纸不完整就不能造）；不能 private/static；**隐含 virtual**（走同一套 vtable）
- **三方对比**：`interface`（提供即可，跨家族）｜ `virtual`（可选改写，有默认实现）｜ `abstract`（必须填空，无实现）
- **接口 vs 抽象类**：can-do vs is-a（不完整）；多实现 vs 单继承；只有签名 vs 签名+实现+字段+构造
- **设计原则：抽象层次要匹配真实差异**——参数化后所有角色伤害算法统一，`abstract` 就该退位（否则只能得到重复代码），这就是**避免过度设计（YAGNI）**

**今天的完整重构演练（可复用的方法论）**
```
09-14 版：if (Name == "剑士") ...                       ← 用数据判断类型 ❌
  ↓ ① 参数化（技能名/加成当构造参数）
消除 if 链，数据直接参与计算                              ← 数据做输入 ✅
  ↓ ② 上提父类（DRY）
Character 收下公共字段 + 统一 CalcDamage；Hero/Monster 只剩构造函数
  ↓ ③ abstract 退位
CalcDamage 从 abstract → 普通方法                        ← 抽象层次匹配真实差异
```
- **重构 ≠ 增强**：重构要求"行为不变"，增强是"行为改变"——**应分成两次提交**（出 bug 时才知道是哪一步引入的）
- **字段封装**：内部实现细节用 `private readonly`（`_` 前缀 + private 才自洽；只由构造函数赋值 → readonly）
- **查找历史版本靠 git**（`git diff` / `git show`），不用在文件里堆旧代码

**属性形态谱系（今日追问整理）**
- **完整属性**（手写 get/set 方法体 + 自己声明 `_age` 字段）← 需要校验/逻辑时用
- **自动属性** `{ get; set; }`（编译器**自建隐藏字段**）← 无逻辑时用；**不能再自己声明字段**（否则两份数据互不同步！）
- 自动属性的隐藏字段**没有名字可访问**；`Age ↔ _age` 的关联在完整属性里是**人写的**，不是编译器自动映射
- **`readonly` 不能修饰访问器**（`{ get; private readonly set; }` 非法）；属性层的"只读"靠**不写 set**
- **`private set`（谁能改）≠ 不写 set/readonly（能不能改）**——两件事

**多态底层（计基随行）**
- 每个类型一张**虚方法表**，对象头部存**类型指针**；virtual 调用 = 取对象 → 查类型指针 → 查表 → 跳转
- 推论：非虚调用更快（编译期焊死）；**静态方法不能 virtual**（没有对象就没有类型指针）；接口调用多一层查找
