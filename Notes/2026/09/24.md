## 今日沉淀

### 一、今天的核心是一次"结构题"，不是"功能题"

三种解法摆在面前时，选的不是"哪个能跑"，而是**"哪个以后改起来只动一个地方"**：

| 方案 | 依赖图 | 代价 |
|---|---|---|
| 乙 · 事件通知 | `BrickSpawner → GameManager` **且** `GameManager → BrickSpawner` | ⚠️ **成环** |
| **甲 · 状态派生（采用）** | `GameManager → BrickSpawner` / `GameManager → ScoreManager` | 每帧一次减法（可忽略），**全图无环** |

**结论**：**上层知道下层，下层谁都不认识。** 以后加"关卡 / 暂停 / 复活"，改动只落在 `GameManager` 一个文件里。

### 二、存量 vs 流量：同一个数字的两种身份

`RemainingBricks` 该用 `_instantiateCount` 还是 `_rentCount`？今天两者**数值相等**，但：

- `_instantiateCount` = **存量**："世界里一共有多少块砖"（由 `Instantiate` 驱动）
- `_rentCount` = **流量**："借出这个动作发生过几次"（由 `Rent()` 被调用驱动）

**哪个是恒等式**：

```
每块砖任一时刻只有两态（在池 / 在场）→ 这是个"划分"
      场上 = N − P               ← 恒等式 ✅
      B − P = 2B − N − R         ← 只有 B = N 时才等于"场上"
```

今天恰好 `B == N`，只因为 `Rent()` 只在 `FillBoard()` 里调、而 `FillBoard()` 只在 `Start()` 里跑**一次**——**这是调用图的巧合，不是两个量的关系**。加"补砖"机制就立刻算错。

**判据**：名字带「次数 / 累计」= 流量；带「总数 / 当前 / 剩余」= 存量。**问"现在"用存量，问"一共几次"用流量**（诊断日志用 `_rentCount` 完全正确）。

### 三、三条"安静的 bug"（今天的主线）

| # | 现象 | 根因 | 破法 |
|---|---|---|---|
| 1 | 球掉出去游戏"卡住"、日志不打印 | `gameManager: {fileID: 0}`（空槽位）→ NRE，**而 `Debug.Log` 写在调用之后 → 被异常截断** | 扒场景 YAML + 看异常堆栈（**证据不是"看着像"**） |
| 2 | `OnClick` 下拉只有 `MonoScript.name` | 把**脚本文件**（项目窗口的 `.cs`）拖进了对象槽；应该拖**层级里的物体**（`Restart()` 是**实例方法**，只有实例调得动） | 下拉里能列出 `Restart()` = 对了 |
| 3 | 赢了却会显示 `GAME OVER` | 守卫只锁了 `Update`（入口），`FailZone → OnBallLost → Lose → End` 是**绕开的侧门** | **入口上锁 ≠ 全局上锁** → 守卫搬到**唯一出口** `End()` |

**三条的共同点**：**编译通过、`ReadLints` 干净、代码"看起来"没问题**——它们只存在于"运行时 + 配置"这一层。

### 四、⭐ 今天最重要的一个原则：**证据要放在能证伪的位置**

```csharp
gameManager.OnBallLost();          // ← 炸在这里
Debug.Log("球掉进了 FailZone");     // ← 被截断，永远不打印
```

| 日志放哪 | 它证明什么 |
|---|---|
| **第一行** | ✅ 「**我到达了这里**」——后面炸没炸是下一件事 |
| **最后一行** | ❌ 「前面全都成功了」——一旦前面有问题，它什么都证明不了，**还给你错误结论** |

> 与错误 12「改完逻辑必须留一个**它在跑**的证据」、09-23「**磁盘才是事实**」同族。

### 五、UI 与世界是两套坐标系

"文字被砖块挡住"的真相是**位置撞车**——`屏幕空间-叠加` 的 Canvas **永远画在世界画面之上**，世界里的精灵**不可能**遮挡 UI。

算一下就清楚：相机 `orthographicSize = 5` → 1 世界单位 = 108px；砖块行 `y = 3.5 / 2.7 / 1.9 / 1.1` → 屏幕中心往上 `+378 ~ +119 px` → **砖块区 ≈ +90 ~ +420 px**，而结果文本被放到了 `y = 150`。

**但"挪位置"是隐式耦合**（改 `origin.y` 就压回来了）。正解是**用结构不用数值**：加一层全屏半透明底板 `Overlay`，把 `ResultText` / `RestartButton` **拖成它的子物体** —— **子物体永远画在父物体之上**（不用手动排序）+ **`SetActive` 有传染性**（一句管三样，还省掉一个字段）。

### 六、计基随行：场景重载清掉什么、清不掉什么

| | 会不会随重载复位 |
|---|---|
| 场景里的 GameObject / 组件 / **实例字段**（分数、对象池、球的位置…） | ✅ **会**（"生命"属于**场景**） |
| **`static` 字段、`Time.timeScale` 等全局设置** | ❌ **不会**（挂在**类型/进程**上，程序集不卸载） |

**所以**：
- `Restart()` **一行都不用写**"分数清零 / 池重填 / 球归位"——那些东西本来就会随重载复位
- 但 `End()` 里借出去的 `Time.timeScale = 0`，**必须在 `Restart()` 里还回来**，否则重开的新一局是**冻结的**

顺手实测的三个答案（`timeScale = 0` 之后）：`Update` **还跑** ｜ `FixedUpdate` **不跑**（物理时钟停摆）｜ **UI 按钮还能点**（EventSystem 用 `unscaledDeltaTime`）。
