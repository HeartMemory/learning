## 今日沉淀

### 一、算法：`98` 验证二叉搜索树（"BST 入门首题"）

- 走**乙法 · 中序迭代**（复用自己 `94` 的显式栈模板），只多养**一个前驱变量**：`if (cur.val <= last) return false;`
- ⭐ **`Pop()` 出栈那一刻 = 中序的「访问点」**（左子树刚走完）—— 这是显式栈版 BST 判定的唯一落点
- ⭐ **越界判据是 `<=` 不是 `<`**：`<` 只抓「下降」，抓不住「持平」，而 BST 要求**严格**递增（`[2,2,2]` / `[1,null,1]` 专抓这一档）
- ⭐ **`int?` 当"还没有前驱"的哨兵**：C# **可空提升比较**让 `cur.val <= null` 自动为 `false`（= 不越界）⇒ **一行特判都不用写**；换成 `int.MinValue` 哨兵会在 `[-2147483648]` 上误判
- ⭐ **"对外签名放得下状态吗？"** —— 乙法只需"一个前驱"（放得下 ⇒ **不必开 helper**）；甲法（上下界递归）要一路带 `low/high` ⇒ **必须开 helper**（wrapper + 递归内核，承 `101`）
- **最大陷阱**：违反常发生在「**远处**」—— 只比每一对父子的写法在官方示例 2 与三组陷阱用例上必露馅；真约束是「**每个节点背着一个由祖先夹出来的值域区间**」（最小反例 `[5,1,null,null,6]`：`6` 的区间是 `(1,5)`，越界）
- ★ 独立裁判 = **BST 定义逐字直译**（对每个节点重扫整棵子树，不下传区间、不剪枝）⇒ 代价 ≈ **Σ(子树大小)**：左斜链 2000 节点重走 **4,006,001** 次 / 28 ms；满树 32,767 节点只有 983,041 次 / 2 ms；正解 O(n) 两组都是 0 ms。三套判题器（裁判自检 / 期望值比对 / 两实现互证）共 **57 项全绿**，网页 **AC**

### 二、C#：泛型收口（"把类型也变成参数"）

- ⭐ `IComparable<T>` 第一次亲手实现：`CompareTo` 的契约是 **负 / 零 / 正**，**不保证是 -1/0/1** ⇒ 判断写 `x.CompareTo(y) > 0`
- ⛔ **比较不能用减法**：`Id - other.Id` 会溢出，而 C# 默认 `unchecked` ⇒ **静默出错**。实测 `10 - int.MinValue` 是**负数**（数学上该是正数）⇒ 排序整体反了。判据：**"比较"用比较，不要用减法**
- ⭐ **`where T : new()` 是"资格"不是"血缘"**：冒号后面看到 `new()` / `class` / `struct` ⇒ 那是**能力要求**；看到类名 / 接口名 / 另一个 `T` 才是**继承 / 实现**
- ⭐ **"有构造函数" ≠ "能 `new T()`"** —— 要的是 **public 无参**那个；手写带参构造会**顶掉**隐式无参构造（`LevelData` 因此被 `new()` 挡在门外 ⇒ **这不是它的问题，是它的设计对**）
- ⭐ **约束只能要"接口里的成员"**：`where T : IComparable<T>` 拿到了 `CompareTo`，但**仍然写不了 `T > T`** —— 运算符不在成员清单里（接口/约束表达不了运算符）⇒ 泛型里"比大小"走 `CompareTo`
- ⭐ **"运行时检查类型"= 白用泛型**：`if (T != typeof(int)) throw` 只对**一个**类型成立、且在**运行期**才拦 ⇒ 那还不如直接写非泛型版本。泛型的全部意义就是**把检查搬到编译期**
- ⭐ 容器按**访问方式**选：`List.FindIndex`（按下标）vs `Dictionary<int, T>`（按 key）—— 同一天在 Unity 那边也用到了这条

### 三、Unity：多关卡真正落地（改名 + 程序化生成 + 相机自动）

- ⭐ **关卡表 = 数据**：`LevelData` 写成**纯 C#**（不继承 MonoBehaviour、不 using UnityEngine）⇒ 能单测、能脱离 Unity 验；Newtonsoft 认 **public 字段**
- ⭐ **`AssetDatabase.MoveAsset` 改场景名**（`SampleScene` → `Level1`）：**GUID 保留** ⇒ 所有引用不断；`Build Settings` 里的路径**自动更新**。判据 = `git status` 显示 **`R`（rename）** ⇒ 「内容一个字节都没变，只是换了名字」
- ⭐ **程序化生成地形**：`Tilemap.ClearAllTiles()` + 按**平台区间表**（`{起 x, 止 x, 顶面 y}`）`SetTile` ⇒ 关卡设计变成**一张可读的表**，改设计 = 改数字重刷
- ⭐ **Tile 的锚点是 (0.5, 0.5)** ⇒ 砖块是**以格子坐标为中心**的 ⇒ 台面**顶边 = 格子 y + 0.5**；再加上 `Tilemap` 自身的 `localPosition.y = -0.2` 偏移 ⇒ **写"站在台面上"的 y 时必须两个都算**（今天敌人/终点"看起来陷进地里"两次都是这里差 0.5）
- ⭐ **相机边界从 Tilemap 自己量**：`localBounds`（局部空间、**已含砖块边缘**）+ `TransformPoint` ⇒ 世界边界；`halfWidth = orthographicSize × aspect`（**每帧算**，窗口一拉比例就变）
- ⭐ **统一判据（x / y 同一套）**：「关卡在某个方向上**装不进**视野 ⇒ 跟随 + 夹取；**装得下** ⇒ 固定」—— 装得下时**不能硬夹**（下界会大于上界，`Clamp` 会一直停在 min，画面贴左）⇒ 改用**居中**
- ⭐ **换关卡的三条判据**：① 「我在哪一关」**不用记**，问场景自己（`GetActiveScene().name` 反查表）② 用**场景名**加载而不是 `buildIndex`（索引会漂移，名字不会）③ **先还 `timeScale` 再 `LoadScene`**（照 `Restart()` 的镜子，否则新场景一开场就是冻结的）
- ⭐ **`-1` 是 `FindIndex` 的"找不到"**：而 `-1 + 1 = 0` 是**完全合法的下标** ⇒ 忘了检查就会**静默加载第 0 关**。⇒ 判据：**"找不到当前关"是数据问题 ⇒ 要红字；"已经是最后一关"是正常进度 ⇒ 只打日志**
- ⭐ **构图与手感**（查证 + 落地）：`yBias`（角色偏下）依据官方 Cinemachine `Screen Y`（0=底 1=顶，官方示范 **0.4**）与平台游戏惯例（跳跃类偏下 8%~12%、攀爬类 15%~25%，⚠️ 上限 25%，再多看不到脚下）；`SmoothDamp` 阻尼（官方 `Lookahead Ignore Y` 那条注明"2D 侧视常用，**避免跳跃时上下颠簸**"⇒ 纵向跟随时阻尼是**必需品**）；死区（官方：Dead Zone 决定"什么时候开始动"）；前瞻（按水平速度朝运动方向多看一点）

### 四、工具链：编辑器被 MCP 打通（基础设施级变化）

- ⭐ 现在可用的不止"只读侦察"：`manage_scene`（场景 CRUD / 层级 / Build Settings）、`manage_gameobject`（增删改 / duplicate）、`manage_asset`（复制资产）、`execute_code`（**在编辑器里跑任意 C#**）等 ⇒ 复制场景 / 刷 Tilemap / 摆对象 / 注册 Build Settings **都能程序化完成**
- ⚠️ **`execute_code` 的代码是「方法体」**：不能声明方法、不能用 C# 7+ 的局部函数（本机编译器是 **CodeDom = C# 6**）⇒ 要写成 lambda / 内联
- ⚠️ **"桥活着" ≠ "本会话能用上"**：MCP 服务器列表在**会话启动时读一次** ⇒ Unity 侧开着、端口也在听，会话里仍可能看不到工具 ⇒ **重启会话**才可见
- ⭐ **断言习惯**：任何 `execute_code` 写入前，第一句就是
  `if (GetActiveScene().name != "目标场景") return "ABORT";`
