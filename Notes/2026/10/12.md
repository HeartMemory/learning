### 一、算法：`105` 分治首题 + 同目录第二笔提速

**题眼一句话**：**前序负责"谁是根"，中序负责"根左右各有谁"。**

前序段首就是根 ⇒ 拿这个值去中序里定位 ⇒ 它左边那堆是左子树全体、右边那堆是右子树全体 ⇒ 切成两个**同型子问题**（分治）。

与 `108` 的分界线：108 是「有序 + 取中点 ⇒ **一步落位**」，本题必须**先找根、再切两半**。

**结构**（承 101 / 108）：主签名装不下"两段区间" ⇒ **wrapper + 外置 helper**（`BuildSubtree(preLo, preHi, inLo, inHi)`，闭区间）；终止条件写成**空区间** ⇒ 一行盖住「空输入 + 空孩子」两个入口（承 104）。

⭐⭐ **今天最贵的一笔：三轮栈溢出**

| 环节 | 内容 |
|---|---|
| 表面症状 | **栈溢出**（不是判错！）—— .NET 的 `StackOverflowException` **不可捕获**，进程当场死，判题器一个字都看不到 |
| 真因 | 闭区间换算漏 `−1` / `+1` ⇒ **三处区间各"多包一格"**（两条中序区间都写出了 `mid`、右子树前序多一格） |
| 不收敛链 | 前序段起点把**根那一格**也划进左子树 ⇒ 那段区间里**找不到它的根** ⇒ `mid` 停在初值 ⇒ 切出的区间与父区间**一模一样** ⇒ 无限递归 |
| ⭐ **不收敛判据** | **某一侧个数为 0 时，另一侧区间长度 = 父区间长度**（左支空 ⇒ 右不收敛；右支空 ⇒ 左不收敛）⇒ 这就是它**第 1 组用例就挂**的原因 |
| 唯一口诀 | **「终点 = 起点 + 个数 − 1」** |

⭐ **三条自查尺子**（写完一秒能验）：

1. **长度守恒**：每个递归调用里，前序区间长度 == 中序区间长度；
2. **中序两侧都不能含 `mid`** —— 承 108 那条「根吃掉的 `mid` 孩子一口不能碰」，**第三次**撞见；
3. **任何前序段的首元素必须就是那棵子树的根**。

**判题器两条新设计**：

| 新招 | 干什么 |
|---|---|
| **⓪-A 尺子自检** | 把期望层序**反序列化后回读前序/中序**，必须与输入一字不差 ⇒ **先证明尺子准，再拿尺子量**（防"我手写的期望值自己就抄错了"） |
| **⓪-B 前提自检** | 查**元素互不相同** + 两数组互为排列 —— ⭐ **"答案唯一"这条命全靠它吊着**：中序里一旦有重复值，"根在哪一位"就不唯一 ⇒ 答案不唯一 ⇒ 判题器① 失效 |

再加**独立裁判 = 题目定义逐字直译**（回读前序/中序）⇒ 与"比对期望值"是**两条独立的路**。

`mid` 初值 `0` 会让「没找到」伪装成「根正好在第 0 位」（上一版栈溢出的**放大器**）⇒ 改 `-1` + `throw`。

**第二笔：换表提速（O(n²) → O(n)）**

把「值 → 中序下标」预存成 `Dictionary<int,int>`，**在 wrapper 里只建一次、递归之外**。

| 刻度 | 升级前 | 升级后 |
|---|---|---|
| 左斜链 1000（单次） | 0.836 ms | **0.082 ms** |
| 左斜链 2000（单次） | 3.322 ms | **0.202 ms**（~16× 快） |
| 右斜链 2000（单次） | 0.146 ms | **0.259 ms**（**~1.8× 慢**） |
| 判据 A（1000→2000） | ~3.9 倍（**平方**） | ~2 倍（🟢 **线性**） |
| 判据 B（左 vs 右，n = 2000） | 差 **24.4 倍** | 差 **0.8 倍**（同量级） |

⭐⭐ 钉死一条判据：

> **空间换时间买的是「最坏情况的界」，不是"每种情况都更快"。**
> 它把 `O(n²)` 压成 `O(n)`，代价是给**原来就便宜的那条路加了常数**（右斜链原本"根在区间最左端一眼撞上"，现在每个节点都要查一次表）。

判据 B 从 24.4 倍 → 0.8 倍，说明「**根在区间哪一头**」对成本的影响被**彻底消掉**了。这与 `700`「O(h) 里的 h 是树高不是节点数」、`199`「同一个词'朴素法'两题成本相反」是同一族：**先问"这一步在重复做什么"，再问"换掉它谁来付账"**。

**防线收口**：`if (!pos.TryGetValue(temp, out int mid)) throw ...` ——
⭐ **`TryGetValue` 的价值不在它写了 `mid`，而在它告诉你有没有写成功**（丢掉 `bool` 就等于把上一版那个 `mid = 0` 的坑原封不动搬回来）。

### 二、C# 主线：存档 / 读档（三态）

`CSharpPractice/2026/10/12/SaveSystem`。

**与 10-08「配置表」的分界**：

| | 配置表 | **存档** |
|---|---|---|
| 谁写它 | 我，随游戏一起发布 | **运行时**，程序自己写 |
| 会怎么坏 | 只可能是我写错 | 断电 / 杀进程 / 磁盘满 / **你自己下一版的代码** |
| 会演化吗 | 不会 | **会**（加新字段是常态） |

**① 落点**：相对路径的基准 = **进程当前工作目录**（`dotnet run` 是项目目录、双击 exe 是输出目录 ⇒ 同一字符串指到两处）⇒ 换**确定的基准** `AppContext.BaseDirectory` + `Path.Combine`。

⚠️ 顺手排掉一个"看起来是正解"的陷阱：**`Path.GetFullPath("save.json")`** 确实给你绝对路径 —— 但它是**拿工作目录当基准**算的 ⇒ 等于把病根**焊死**在代码里。
⭐ 判据：看这个路径**是从哪个基准长出来的**，而不是看它**长得像不像**绝对路径。

⚠️ `Path.GetTempPath()` 也不行（临时目录会被系统**清理**）—— 基准的选法取决于**这个文件该活多久**。

**② 三态读取**：`Loaded` / `NotFound` / `Corrupted`。

⭐ **一个 `bool` 装不下三态**：「第一次玩」是**正常情况**（新玩家），「存档坏了」要**告诉玩家**（他的存档没了）—— 一个 `bool` 做不到"既降级、又报警"。

| 实际发生 | 谁说出来 | 归哪一态 |
|---|---|---|
| 文件不存在 | `FileNotFoundException` | `NotFound` |
| 读不了（占用 / 权限） | `IOException` / `UnauthorizedAccessException` | `Corrupted` |
| 不是合法 JSON | `JsonException` | `Corrupted` |
| **内容是合法 JSON、但正好是 `null`** | ⚠️ **没有异常**（只能判返回值） | `Corrupted`（判据链：文件在 ⇒ 不是 `NotFound`；内容不能用 ⇒ 只剩它） |

**③ 今天踩链（编译器一路在抓契约）**：

| 报错 | 意思 |
|---|---|
| **CS0177** | `out` 参数「**每个出口都必须赋值**」是编译器强制的契约 —— 把赋值挪进 `try` 之后，`catch` 里也得自己赋 |
| **CS0161** | 「加分支 ≠ 换分支」：插 `if` 时**别删**后面那句无条件的 `return` |
| **CS8601** | `Deserialize<T>` 返回 **`T?`** ⇒ 用**可空局部变量**接住，判完再赋给非空目标 |

⭐⭐ 最关键的判据（判题器④ 四绿实证）：

> **JSON 里没有的键 ⇒ 反序列化后取【属性初始值】**（不崩、不抛、也不是 null）
> ⇒ **"旧存档缺字段"是免费演化** —— 加新字段时，**一行迁移代码都不用写**。

**④ 还有一条元判据**：

> **契约变了，「报告坏消息」的手段就得跟着换** —— **异常 / 返回值 / 枚举**，三选一，别在一段代码里混着用。
> 实例：10-08 那句 `levels ?? throw new InvalidDataException(...)`（抛型）与今天的 `parsed is null → return Corrupted`（Try 型）**兜的是同一件事**（"解析成功、但交出 null"），只是**报告手段**换了。

**⑤ 另一条元判据**：

> **"坏"有两种** —— ① **读不出来**（用**异常**报告）② **读出来了，但内容不成立**（用**返回值**报告）。
> 第二种**永远不会抛** ⇒ `catch` 写再多也接不住它。

### 四、计基随行（10 min）：文件 IO 与编码

- IO 是 **两层**：**字节层**（`FileStream` / `byte[]`）/ **文字层**（`StreamReader` / `Encoding`）/ **打包层**（`File.ReadAllText`）。
- **编码就是那张"字节 → 字符"的翻译表** —— UTF-8 下一个中文 = **3 字节**；`Encoding.Default` 在 .NET Framework 是本机 ANSI、在 .NET Core+ **变成 UTF-8**（老代码"突然乱码"的经典来源）。
- **BOM**：`UTF-8 with BOM` 会在文件开头多 3 个字节（`EF BB BF`），某些解析器看到就炸；`File.ReadAllText` 会自动吃掉它。
- **相对路径的基准 = 进程当前工作目录**（不是 exe 目录）⇒ `AppContext.BaseDirectory` 才是"确定的基准"。
- **异常家族按"从哪来"记**：`ArgumentException` 系（参数本身不对）/ `FormatException`（字符串长得不对）/ `IOException` 系（子类含 `FileNotFoundException`、`DirectoryNotFoundException`）/ `UnauthorizedAccessException`（**不在 `IOException` 那一支**）/ `JsonException`（⭐ 与 IO 家族**不沾亲** ⇒ `catch (IOException)` 接不住它）。
- **`catch` 两条规矩**：① **只接你能处理的**（接住却什么都不做 = 把症状藏起来）② **具体在前、父类在后**（写反 = **CS0160**）。
- 判据：`catch` 里**三选一** —— 就地修复 / 补充信息后重新抛 / 明确降级。「四不像」就是 bug。
