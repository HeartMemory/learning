## 今日沉淀

### 一、104：递归的两种"答案流向"（今天的分水岭）

| | **收集型**（144 / 94 / 145） | **返回型 · 分治**（104） |
|---|---|---|
| 外层方法 | 备容器 `List<int>` | ⭐ **不需要容器** |
| 递归函数 | 另写 `Walk(node, result)` | ⭐ **就用自己**，不开小号 |
| 答案怎么走 | 通过**参数**往下流、路过一个装一个 | 通过**返回值**往上浮、逐层合并 |
| 返回类型 | `void` | `int`（**返回值就是答案**） |
| 终止条件 | `return;`（什么都不交） | `return 0;`（⭐ **必须交一个值回去**） |
| "装自己"那行 | `result.Add(node.val)` | 变成**最后那一步合并** |

⭐ 一句话判据：**收集型用参数传"篮子"，分治用返回值传"结论"。**
⭐ 由此也解释了"为什么 144/94/145 只差一行、而 104 完全换了个形状" —— **前三题的差别在"装自己的位置"，今天的差别在"答案走的方向"。**

### 二、⭐ 两条实测钉死的错法症状（断崖 ≠ 平移）

两条都不是"想"出来的，是**临时副本各跑一遍 15 组**量出来的：

| 错法 | 实测症状 | 绿/红 |
|---|---|---|
| **漏掉 `+1`**（`return Math.Max(左, 右);`） | ❗**整棵树恒为 0**（不是"少 1"！终止条件给 0，此后**没有任何一层加过东西** → 零 + 零 = 零，树多高都一样） | **13 红 2 绿** |
| **边界值取 `-1`**（`if (root == null) return -1;`） | ❗**整棵树统一少 1**（每个节点的答案整体平移一格；空树返回 -1） | **15 组全红** |

- ⭐ 两条判据：
  1. **"漏 `+1`"和"边界值选错"不是同一种病** —— 前者让答案**断崖式归零**，后者让答案**整体平移**。能分清，才算真懂"递归返回值怎么累积"。
  2. **假绿比红更危险** —— 漏 `+1` 时**空树那组是绿的**（期望 0、结果也 0）。用例里必须同时有"深度 1"（单节点）和"深度 4"（深树），才能把"恒为 0"和"平移一格"分开，也才不会误以为"至少对了一部分"。

### 三、一条风格判据：终止条件已覆盖的入口，再写分支就是重复

初版递归版里写了两道多余的防线：`if (root.left == null && root.right == null) return 1;`（叶子特判）+ 两处 `if (... != null)`。
实测：**把 6 行压成 2 行，仍然 15/15**（临时副本验证）。

- 机制：`if (root == null) return 0;` 这一行**同时盖住三个入口**（空树 / 叶子的左孩子 / 叶子的右孩子）→ 叶子的两个孩子各命中一次终止条件、各得 0 → `Max(0,0)+1 = 1` ✓
- ⭐ 判据：**当终止条件已经覆盖某个入口时，为那个入口再写一条分支就是重复。** 它增加的是**读者的认知负担**（要花几秒验证"这个特判是不是必要的"），不是正确性。
- 承 144 那条：**"最小情况写在函数入口一处 = 一行盖三入口"** —— 这两行 `!= null` 正是"没真正信这句话"的痕迹。
- 同步修正了脚手架与索引里的错误说法（原写"全局统一少 1"）。

### 五、探针：**我主动问** vs **等引擎说**

| API | 它问的是 | 时机 |
|---|---|---|
| `Physics2D.OverlapCircle(点, 半径, 掩码)` | "以某点为心的圆压到了哪些层？" | ⭐ **现问现答、无延迟**；形状/位置/层三个维度都可控 |
| `OverlapBox` / `OverlapCapsule` | 同上，换盒子/胶囊 | 盒形更贴"脚掌" |
| `Physics2D.Raycast(起点, 方向, 距离, 掩码)` | 打一束**无限细**的线 | 便宜，但太窄 → 边缘/斜地易漏 |
| `Collider2D.IsTouchingLayers(掩码)` | "我有没有碰到某层？" | 省事；⚠️ 读的是引擎**已记录**的接触数据 → **慢一拍** |
| `OnCollisionStay2D` + `normal` | "刚才碰到谁、什么方向" | 信息最全，**慢一拍** + 方向要自己解析 |

⭐ 判据：**"查询类"是我主动问，"回调类"是等引擎说** —— 前者"问什么形状、问哪个点、问哪一层"都在你手里，这就是**手感可调的来源**。

**返回值的单位是"有没有"**：`OverlapCircle` 返回 `Collider2D` 或 `null` → 一次"引用是否非空"的判断。
- ⚠️ 用 `!= null`，**别用 `is not null`** —— Unity 重载了 `==`/`!=` 能识别"已销毁物体"，`is null` 走纯 C# 引用语义、**绕过**这层保护
- ⚠️ 第 3 个参数是**掩码**不是层号：`0` = 谁都不问（**永远不接地**）；`-1` = 全都问（**包括你自己**）
- 用**单数版**（`OverlapCircle`），别为"有没有"去分配数组

### 六、⭐ 探针会命中**玩家自己** → 掩码不是可选项

- 圆心就摆在自己碰撞体的**底边**上 → 圆往上探的那部分**压在胶囊里** → 不加层过滤就**永远算接地**（症状：跳不高 / 空中乱跳，且**控制台一声不响**）
- ⭐ 判据：**"查询类" API（Overlap / Cast）必须配层掩码，因为它们连你自己都会撞**；而 `OnCollisionEnter2D` 回调**天然不会**把自己的碰撞体报给自己 —— 这就是两条路在机制上的核心差别
- 场景文件里的证据：`groundLayer: m_Bits: **64**` = `0100 0000` = **`1 << 6`**（只勾了 `Ground`）→ **位运算在 YAML 里现形**
  - 若再勾上 `Player`(7) 就会变成 `192` = `1100 0000`（`64 | 128`）→ **勾选 = 或运算的累加；检查 = 与运算取交集**

### 七、⭐ 边沿 vs 电平 → **意图标志位**（两种时钟之间的桥）

| API | 类型 | 按住空格 3 秒 |
|---|---|---|
| `IsPressed()` / `ReadValue<float>()` / `.phase` | **电平**（"现在是什么状态"） | **刷屏 true** |
| **`WasPressedThisFrame()`** / `WasReleasedThisFrame()` / `WasPerformedThisFrame()` / `triggered`(老写法) | **边沿**（"变化刚发生那一瞬间"） | ❗**只出现一次** |

- ⭐ 判据：**要"跳一次"用边沿；要"持续施力"用电平**（挡板的 `ReadValue<Vector2>().x` 是电平，因为它要的是"你**正推着**"）
- ⭐ **`WasPressedThisFrame()` 是"帧级"语义** → 只有在**动作被更新的那一帧**为真。项目级 Actions 默认在 `Update` 更新 →
  - 在 `Update` 里读 ✅
  - 在 `FixedUpdate` 里读 ❌：一个渲染帧有 **0~N 个**物理步 → 要么**漏读**、要么**重读**
- **所以"意图标志位"不是多余的中间变量，而是两种时钟之间唯一的桥**（承 09-18 的"双时钟"）。

### 八、一个物理步只提交一次速度

`y` 有三个去处（起跳 / 落地归零 / 原样保留）→ **先在 `if` 里合成一个 `y`，最后一次性 `linearVelocity = new Vector2(x, y)`**。
- 判据：**分两次赋值 → 后写的覆盖先写的**（谁后写谁赢，且这种 bug 在满速移动时可能看不出来）
- `y` 的决策要用**取出来的那一份**（先 `float y = _rb.linearVelocity.y;`），因为它同时被三处判断使用

### 九、⭐ 传感器的"跟不上那一瞬"（今天最值钱的一条）

- **现象**：起跳后头一两步，**探针还压在地里**（圆心才抬升约 0.14）→ 会**再次判定"在地面"**
- **后果**：若回满次数写成 `if (isGrounded) _jumpsLeft = maxJumps;` → 次数被**非法回满** → 空中连点**白送跳次**
- **正解**：只写一个条件 —— **`if (isGrounded && y <= 0f)`**（**停住或下落**时才回满）。刚起跳时 `y = +jumpSpeed > 0`（正在上升）→ 不回满
- ⭐ 通用判据：**"用传感器判断状态"时，必须考虑"状态刚改变的那一瞬间传感器还没跟上"** —— 脚步声、贴墙、土狼时间都是同一个坑

### 十、手感公式与调参工作流

```
跳跃高度  h = v² / (2g)          g = 9.81 × gravityScale
保持高度不变时：  v ≈ 7 × √(gravityScale)
```

| 想要的感觉 | `gravityScale` | 同步的 `jumpSpeed` | 高度 |
|---|---|---|---|
| 月球感 | 1 | 7 | 2.5 |
| **今天定格** | **2** | **10** | **≈ 2.55** |
| 更实 | 3 | 12.1 | 2.5 |
| 很重 | 4 | 14 | 2.5 |

- ⭐ 顺序不能反：**先用 `gravityScale` 定"重量感"，再用 `jumpSpeed` 定高度**（高度对 `v` 是**平方**关系：想跳高一倍，`v` 要 ×1.414）
- 屏幕范围：相机 `orthographic size = 5` → 竖直 **y ∈ [-5, +5]**；Player 站住时 **y ≈ -2.0** → 最高点约 **+0.55**（不会冲出屏幕）
- ⚠️ 调参工作流：**在 Play 模式里实时调**是最快的（"播放模式改动不保存"这次是**正面用法**：拿它当试衣间）→ 满意后**记下数字** → **退出 Play** → 在非播放模式下**重填一遍** → **场景 `Ctrl+S`**
