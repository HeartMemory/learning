## 今日沉淀

### 一、算法：`199` 二叉树的右视图（"102 只换一处"首题）

- 装备**全复用 102**（队列 + `int times = q.Count` 取在 `for` **之前**），唯一改动 = **每层只收【最后一个】出队的节点**（`if (i == times - 1) result.Add(cur.val)`）→ 循环结束时的 `cur` 恰好是本层最右
- ⭐ 判据：**右视图 =「每一层最右」** —— 与 102「每层全收」只差**收几件**。空树返回**空列表**（不是 null、不是 `[[]]`）
- ⛔ **三组陷阱用例专抓「答案来自左子树」**：左支更深时，最深一层的答案就在左支里 → **一路向右收集的写法必露馅**
- 值域含 **0 与负数** ⇒ **不能用 0 当"这儿没人"的哨兵**
- ★ **独立裁判 = 定义逐字直译**：对每个深度重走全树取最右（**明知能剪枝也不剪**，≈ h×n）→ 三套判题器（**裁判自检** / 期望值比对 / **两种实现互证**）共 **42 项全绿**
- ⭐ **与 110 的对照（今天最硬的一条）**：**同一个词「朴素法」，在两题里成本结构相反** —— 110 的朴素裁判在斜链上**反而便宜**（根上一眼就崩、只付一次全树高度），本题裁判 ≈ h×n 在斜链上**最贵**。⇒ **真判据 = 它到底在重复做什么**，不是背复杂度标签
- ★ 代码清理一条判据：**「占位对象」与「`!` 运算符」是同一类东西** —— 都把"类型的保证"换成"我的口头保证"（正解 = 让 `cur` **只活在循环里** + `i == times - 1` 收答案 ⇒ 结构自己保证"收的一定是本层最后一个真节点"；⚠️ 写 `i == times` 是**死代码**）

### 二、Unity：通关闭环（"哨兵 / 裁判 / 唯一出口"的第二次落地）

- `Goal` 与 `FailZone` **只差"喊哪一句"** ⇒ 哨兵的职责只有两件：**判层 + 上报**
- **「死」与「赢」共用同一把幂等锁** ⇒ 玩家最后一步同时压中 `Goal` 与 `Failzone`，也只结算一次
- 结算面板升级为**「死 / 赢共用」**：**同一块 Overlay、两个入口**，只多一个 `resultText` 引用 + 一个 `ShowWin`
- ⭐ 判据：**需要区分的订阅者订两条事件（要写不同文本），不需要区分的订一条** —— "一个语义一个家"

### 三、Unity：地图重做（40 宽 · 全实心台地）

- ⭐⭐ **实心台地 vs 1 格厚悬空薄板**（今天最大的一条设计判据，见"三句话复盘"第 1 条）
- **落差用实心侧壁过渡** ⇒ 角色撞上去必须跳（不再是"悬空板旁边一个没意义的 1 格空当"）
- **消灭一切 1 格设计**：1 格宽洞 / 1 格高缝 / 1 格宽台 **一律不做**
- 地形底 `cellY = −8` 与相机视野下界 `−7` 配合 ⇒ **玩家永远看不到地形底下**
- **唯一挖穿的深渊（4 格）** ⇒ 掉下去一路到判定区；其余落差全是"自由落体到安全区"
- 抬升全表 **≤2**（单跳 2.55），只留 **1 处 +3** 要二段跳

### 四、Unity：`CameraFollow`（相机跟随）

- ⭐ **"跟"必须排在"动"之后** ⇒ 只能放 `LateUpdate`（`Update` 之间谁先谁后是**未定义**的 → 会抖）
- 写回 `transform.position` 必须"**取出 → 改 → 整体写回**"（承 10-05 的 **CS1612**：属性返回 struct）
- ⭐⭐ **"出屏即死"为什么成立**：相机夹取位是按"**关卡边界对齐屏幕边界**"算的 ⇒ **相机被夹住处正好是关卡两端** ⇒ **出屏 = 出关卡**自动成立；而**相机在中间时玩家永远在屏内**（不需要额外处理）。**上和下不设这条线**
- ⚠️ 隐患（排 **10-10 打磨日**）：`minX` / `maxX` 现在按 **16:9 写死**，而它们其实是**屏幕宽度的函数**（`halfWidth = orthographicSize × aspect`）—— 分辨率一变，"屏幕外沿 = 关卡边界"就不成立了

### 五、Unity：层的"兼职"问题 + 订阅语义

- `EnemyPatrol` 的"脚前探针"与"撞墙射线"**共用一个 `groundLayer`** → 拆出独立的 `obstacleLayer`（勾 `Ground + Hazard`）
- `Goal` 进 **`Hazard` 层** ⇒ 敌人**提前看到终点**（射线能命中触发器），**不再穿模**；玩家完全不受影响（接地探针只查 `Ground`）
- ⭐ **`OnGameEnded` 统一语义**：把"停手"从订 `OnGameOver`（死）改成订**"游戏结束"** → 修掉「**通关后还能转身**」

### 六、工程：MCP 协作的三条实测（今天新踩）

- **瓦片换完，`CompositeCollider2D` 的几何体会"慢一拍"** —— 同一次调用里读到的是**上一批的旧值** ⇒ ⭐ **派生数据要隔一帧再读**
- **模态对话框会阻塞编辑器主线程** ⇒ MCP 桥 ping 不应答（但进程仍 `Responding = True`，因为 Windows 消息循环在伺候对话框）
- **`BoxCollider2D.size` 是本地尺寸，会被 `localScale` 再乘一遍** ⇒ 想改大小**只动其中一个**（`scale` 或 `size`），**两个一起动 = 平方**（`Goal` 就这么被我搞成过 1×4）
