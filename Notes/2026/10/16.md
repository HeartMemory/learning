## 今日沉淀

### 一、算法：`236` 二叉树的最近公共祖先

**题眼一句话**：**«两棵子树的答案怎么合起来»** —— 而本题的返回值**第一次装的是「节点」**（不是数、不是形态、不是指针别名）。

**⭐ 与前 16 站的血缘**：`null` = 空手而归 —— 承 98 的 `int?` 哨兵、230 的 `bool isfound`，同一句话：**"什么都没有"要靠类型说，不靠魔法值说**。

**⭐⭐ 四格合并表（全题就这一张表）**：

| 左支带回 | 右支带回 | 当前节点该交回什么 |
|---|---|---|
| 空 | 空 | `null`（原样空手） |
| **非空** | 空 | **原样上传那一侧** ⭐「线索不能扔」 |
| 空 | 非空 | 同上（**对称的，别只写一半**） |
| **非空** | **非空** | **就是我自己** ← 「**最近**」两个字的唯一落点 |
| 命中 p 或 q | — | **交出我自己**（**剪枝保留**：答案不可能比目标本身更深） |

**★ 三个真实踩坑（按发现顺序）**：

| # | 现象 | 判据 |
|---|---|---|
| ① | 用**两格 bool**（"这一支找到了谁"）时，**父子关系**（p 是 q 的祖先）下**没有任何一层产生答案** ⇒ 返回初值、看着像"碰巧对" | ⭐ **"信息不足病" ≠ "覆盖病"**：门（守卫）只治"答案被祖先改掉"，治不了"压根没人下结论"；后者只能**换返回值装什么** |
| ② | 元组顺序改了、条件却复制粘贴成两遍 | **元组匹配靠位置、名字只是标签**（顺序反 = 把"找到 p"记成"找到 q"）；**复制粘贴后逐字念一遍** |
| ③ | `Walk(...)` 的返回值接住了、却没往外传 | **算了却没交出去 ≈ 没算**（🪞 承 114 丢掉 `RotateTowards` 返回值 = 什么都不发生） |

**判题器设计（本站新增一条）**：⭐ **引用同一性** —— "你返回的是不是树上**原来那个对象**"（拦 `new` 一个同值节点交差）。它同时也是"**答案唯一 ⇒ 敢比对期望值**"的前提（承 105 的 ⓪-B：唯一性全靠"元素互不相同"吊着）。
六项独立裁判：同一性 / 是祖先 / **最近**（两个孩子都不能是共同祖先）/ 没改树 / 幂等 / **定义逐字直译**（把全树铺平、逐个问"你俩子树里有没有 p、q"，记**最深**者，**明知能剪枝也不剪**）。

**性能对账**：净值 **0.3669 ms**（平衡树 n = 100,000、p/q = 最左 / 最右叶 ⇒ 答案 = 根，几乎走满全树）
vs **直译裁判**：500 → **250,003** 次 ／ 1000 → **1,000,003** 次 ／ 2000 → **4,000,003** 次 ⇒ **翻倍 ×4 ⇒ 平方阶**。

**阶梯区（栈顶尺子）**：左斜链 8000 ✅ → **16000 💥 栈溢出**（爆点栈上 **12,035** 个 `Walk` 帧）
⇒ ⭐ **与 230 对账钉死一条新判据**：**同一台机器，栈帧大小随「参数 + 局部变量」变** ——
230 的 `Walk(1 参 + 1 局部)` ≈ **43 B/帧**（爆点 24,062 帧）↔ 本题 `Walk(3 参 + 2 局部)` ≈ **87 B/帧**（爆点 12,035 帧）⇒ **深度上限直接砍半**，与算法对不对无关。

### 二、Unity 主线：地面网格 + 跳跃 + 地面探针 + Gizmo（🏆 闸门②）

**① 地面改「1 米一格」网格**（`GridLine.png` 贴图 + `GroundGrid.mat`，`Tiling = 50 × 50`）
⭐ **关键账：贴图尺寸决定线宽** —— `线宽（米）= 1 ÷ 贴图边长`：

| 贴图边长 | 一格 = 1 米时的线宽 | 观感 |
|---|---|---|
| 128 px | **0.8 cm** | 屏幕上不到 1 px ⇒ **看不见**（第一版就是这个） |
| 16 px | 6.25 cm | 偏粗 |
| **32 px** | **3.1 cm** | ⭐ **甜点**（细而清楚） |
| 64 px | 1.6 cm | 开始断续 / 闪烁 |

+ ⭐ **mipmap 的代价**：远处格子淡化 —— 这不是 bug，正是它换掉**摩尔纹**的代价。
+ 副产品：**格子 = 米尺**（1 格 = 1 米）⇒ 跳跃高度、移动速度都能"用眼睛量"。

**② 跳跃**：`jumpSpeed = 6.3` ⇔ 约 **2 米**（公式 `v = √(2·g·h)`，g = 9.81）
⭐ **3D 没有 `gravityScale`**（反射查死：`hasGravityScale = False`）—— 平台游戏里 2D 的 `gravityScale = 2` **在 3D 无对应物**；3D 想改重力只有两条路：全局 `Physics.gravity` 或自己施加加速度。
⭐ 跳跃的语义是**边沿**（`WasPressedThisFrame` + 意图标志 `_jumpRequested`），与冲刺的**电平**（`IsPressed`）正好相反 —— **同一个输入系统里两种语义并存**。
⭐ 三件事的顺序不能换：**先算接地 → 再决定跳 → 最后清意图**（清早了丢跳、清晚了连跳）。
⭐ 今天**正式打破**了 10-14 立的判据④「别碰 y」—— 但只准**一处**破（`Jump()` 里覆盖 y）；水平那段继续"一根手指都不碰 y"。
⭐ 覆盖式而非累加式：`v = _rb.linearVelocity; v.y = jumpSpeed; _rb.linearVelocity = v;`（🪞 与 10-06 敌人追逐"覆盖式速度"同族）。

**③ 地面探针 = 组合拳（今天的技术核心）**

| 探针 | 问什么 | 为什么非它不可 |
|---|---|---|
| `Physics.CheckSphere` | "**脚下这块球**里有没有地面" | **有体积、没方向** ⇒ 站在平台边缘**不说谎** |
| `Physics.Raycast`（向下短线） | "**这个面斜不斜**" | ⭐ 官方原话：**要真法线就用 Raycast**（`SphereCast` 的 `hit.normal` 常是"接触点→球心"，不是表面法线） |

**两条官方坑（都直接影响写法）**：
- ⛔ `Raycasts will not detect Colliders for which the Raycast origin is inside the Collider.` ⇒ 起点必须**抬离地面一点点**（`groundCheckLift = 0.02`）；且 `lift < groundCheckDistance`（否则射线末端够不到地面 ⇒ 永远跳不起来）
- ⛔ `QueryTriggerInteraction.Ignore` 要**写死**（别用默认的 `UseGlobal`）—— 行为别被全局设置牵着走；将来脚边飘个金币触发器也不会误判

**坡度判据**：`Vector3.Dot(hit.normal, Vector3.up) >= Mathf.Cos(maxSlopeAngle * Mathf.Deg2Rad)`
⭐ **"能站的最大坡度角"本身就是那个阈值**（45° ⇒ 0.707）—— 这不是魔法数，是**设计参数**；🪞 它也正是 UE `WalkableFloorZ = 0.71` 的由来。

**④ Gizmo 可视化**：球（= `CheckSphere`）+ 向下的线（= `Raycast` 的 `maxDistance`）+ 起点小白点；颜色 = `_isGrounded`（绿 = 接地 / 红 = 悬空）。
⭐ **"测的地方"和"画的地方"必须是同一个点** ⇒ 把起点抽成一个**只读属性**（`GroundProbeOrigin`），两处都读它（🪞 承 `CameraFollow.Yaw`：**一个状态只能有一个家**）。
⭐ **谁有特殊需求，谁自己付代价**：**编辑器期 `Awake` 不跑**是"编辑器期"的问题 ⇒ 兜底搬进 `OnDrawGizmosSelected`，**运行期热路径不做任何兜底**（`_col` 的家是 `Awake`，那儿有"响亮地失败"的自检把 null 这条路堵死）。
⚠️ 顺带纠正一个说法：省下的那点判断开销**小到无感** —— 真正的理由是**职责分离**，别把"设计清晰"说成"性能优化"。

| 坑 | 现象 | 判据 / 解法 |
|---|---|---|
| **① 编译产物没跟上源码** | 代码改了、控制台 0 红字，但运行行为仍是上一版（"导入层新、编译层旧"） | ⭐ 判据 = **`Library/ScriptAssemblies/Assembly-CSharp.dll` 的时间戳**；另可看编辑器状态里的 `last_compile_finished`。**"没红字" ≠ "编译过了"** |

**另一条今天新学到的 API 语义**：Gizmo 其实有**两级**开关 —— Scene 视图的**总开关** + Unity 按**脚本类型**单独登记的可见性（`GizmoUtility` 里那套）。

**还有两条"看着像玄学、其实有明确机制"的**：

| 现象 | 机制 | 判据 |
|---|---|---|
| `_col ??= GetComponent<CapsuleCollider>()` **永远补不上**、每次都走兜底 | `??=` 走 **CLR 的"真 null"检查**，**绕过** Unity 给 `UnityEngine.Object` 重载的 `==`；退出播放 / 域重载后旧引用是"**假 null**"（引用在、对象已销毁）⇒ `== null` 判 true、`??=` 判"不必赋值" | ⭐ **Unity 对象判空一律写 `== null`**，别用 `??` / `??=`（`?.` 同理） |
| 探针起点跑到"左下角" | `bounds.min` 是**包围盒的一个「角点」**（x、y、z 三个分量**全取最小**），不是"最低高度" | ⭐ 取一个点的坐标时，**三个分量分别问"这个分量该来自哪"**；正解 = x/z 取 `bounds.center`、y 取 `bounds.min.y` |

### 四、计基随行（10 min）：3D 数学下半场 + 物理材质

- **点乘 = cos 夹角**（两个单位向量时）：平地 **1** ／ 45° **0.707** ／ 60° 0.5 ／ 垂直墙 **0** ／ 天花板 **−1**
- ⭐ **"能站的最大坡度"这个设计意图，本身就化成那个阈值**（不是"我凑了一个数"）
- 探针的**时机**：射线 / 球查询是**主动问**（"现在有没有"）；2D 那套"真接触 + 法线朝上"是**事后通知**（慢一拍、粒度是"碰撞体对"）⇒ **"已经发生"订回调、"接下来会不会"发探针**
