| | 104 求高度 | 226 翻转 |

### 二、元组赋值：**右侧先算完 = 编译器替你开的临时变量**

```csharp
(root.left, root.right) = (root.right, root.left);   // ❌ 会"丢一半"的两行赋值的对照版
```

| 实测项 | 结果 | 判据 |
|---|---|---|
| `(a, b) = (b, a)` | 交换成功 | — |
| `(x, x) = (y, z)` | `x = z` | ⚠️ **不是"同时赋值"**：右侧是**快照**，左侧仍**从左到右顺序写**（后写覆盖先写）|
| 属性交换的求值顺序 | `读 Q → 读 P → 写 P → 写 Q` | ⭐ **右侧全部求值完才开始写左侧** —— 这就是"临时变量"的硬证据 |
| 不借临时变量（两行直接赋） | `读 Q → 写 P → 读 P → 写 Q` → **丢值** | 226 错法 C 的机制 |
| 真身类型 | `System.ValueTuple<int,int>`，`IsValueType = True` | **值元组**（结构体、无堆分配）；旧 `Tuple` 是引用类型 |
| 左边放只读属性 | **CS0200** | 左边每项必须是**变量** |
| 左边放"属性返回的结构体成员" | **CS1612**（"不是变量"） | ⭐ 正是 `_rb.linearVelocity.y = 3` 编译不过的原因 → **必须先取出来再整体写回** |

### 三、⭐ 四种错法指纹（**实测**，满树三层，正确 = `[1,3,2,7,6,5,4]`）

| 错法 | 实测输出 | 指纹 |
|---|---|---|
| A 只递归不交换 | `[1,2,3,4,5,6,7]` | **原样返回**（但空树/单节点/左右同值会**假绿**）|
| B 只换根一层 | `[1,3,2,`**`6,7,4,5`**`]` | **开头两个数完全正确**（最阴）|
| C 交换没留临时量 | `[1,`**`3,3,7,7,7,7`**`]` | **值重复**（同一支塞给两边，原左支整支消失）|
| 中序字面版（左→换→右） | `[1,3,2,6,7,4,5]` | ⭐ **与 B 完全撞车** |

⭐ **由此钉死一条判据：「看症状反推病因」有边界** —— 104 那天"断崖 vs 平移"可分是**运气好**；今天撞上"**三种病因同一个指纹**"，就只能**回去读代码**。
⭐ 另一条：**顺序自由的真正来源不是遍历顺序，而是"两个孩子先绑进局部变量（快照）"**（绑定版任意顺序都对）；中序要成立，第二次递归必须写 `.left`（交换后跑到左边的那一支）。

### 四、递归 → 迭代的"语义漂移"（错题本级的坑，但今天只算学习内容）

迭代版里把交换写成 `(root.left, root.right) = (root.right, root.left)`（**该写 `cur`**）→ **7 次交换全砸在同一个对象上** → 翻转是**对合**的 → **奇数次 = 净翻一次 = 只翻了根那一层** → 输出 `[1,3,2,6,7,4,5]`（**又是那个指纹**）。

⭐ 判据：**递归 → 迭代时"当前节点"会换人**。递归版 `root.left` 里的 `root` 就是当前节点；一进循环当前节点变成 `cur`，而 `root` 悄悄退化成"**那个永远不变的根**"。

### 五、Tilemap 全链路（今天真正落地的九样东西）

```
精灵（Square.png 256px/PPU 256 → 世界 1×1）
  └─ 瓦片 Tile（.asset：精灵 + ⭐ 碰撞体类型 = 网格 + 颜色）
       └─ 调色板（Tile Palette 窗口 + 调色板资产 .prefab）
            └─ Grid（单元格 1×1）+ Tilemap（子物体，TilemapRenderer）
                 ├─ ⭐ 层 = Ground（探针只看这一层）
                 ├─ Tilemap Collider 2D（按瓦片铺形状 → 一格一个方框）
                 ├─ Composite Collider 2D（合并器）+ 它自带的 Rigidbody 2D（**主体类型 = 静态**）
                 └─ ⭐ Tilemap Collider 的「合成操作 = 合并 (Merge)」（把两者接上）
                      └─ 摩擦 0 材质（玩家侧 + 地形侧都挂）
```

**两块碰撞体的分工**：**`TilemapCollider2D` = 生成器**（懂瓦片数据，铺出来是一格格方框）；**`CompositeCollider2D` = 合并器**（**完全不懂瓦片**，只收"别人交给它的形状"）。不合并的代价：① 性能（内部边全在）② **手感**（走过格子接缝会"卡边"）。
**合成操作 = 几何布尔运算**（官方原文）：`Merge` = **OR 并集** ／ `Intersect` = AND 交集 ／ `Difference` = NOT 差集 ／（面板里那项"翻转"）= **XOR 异或** → 与 `136` 的"全场异或"同一族思想，只是作用在**形状**上。

### 六、⭐ 三条硬事实（都是今天实测出来的）

1. **瓦片单元格 `(x, y)` 占据世界 `[x, x+1] × [y, y+1]`（原点在左下角）**
   - **自证方法**：读场景里 `m_CompositePaths` 的顶点 —— `(10, −4) → (−10, −4)` 那条水平边就是**地面顶面 = −4**（格 `y=−5`）
   - 教训：我一度用"格中心 = 世界坐标"推算，**整体错了 0.5**，导致一晚上的对照表全是错的
2. **角色静止时悬空 0.02 是"接触皮肤"，不是 bug**
   - `项目设置 → 物理 2D → 默认接触偏移 (Default Contact Offset) = 0.01`（+ 求解器余量）
   - 换算：相机正交 6 → 12 世界单位高 ÷ 1080 px → **0.02 ≈ 2 像素** ← 就是那条反复看到的蓝线
   - 想消：把默认接触偏移改成 `0.005`；或上 **Pixel Perfect Camera**（归 10-10 打磨日）
3. **⭐ 通道净空必须留余量：零净空时"圆能擦过去、方一定过不去"**

| 净空 − 碰撞体尺寸 | 圆 | 方框 |
|---|---|---|
| ≥ 0.2 | 轻松 | 轻松（更稳） |
| 0.05 ~ 0.2 | 能过 | 勉强 |
| **0（正好一样大）** | **切点 → 能"擦"过去** | ❌ **一定过不去**（等长边 + 0.01 接触偏移 → 被顶在门口） |

⭐ 判据：**"能不能过"只看「净空 − 尺寸」，与形状无关**；形状只决定"余量小时谁更宽容"。**平台游戏惯例：通道 ≥ 角色高 × 1.5**。

### 七、器材坑（四个，都是"菜单/类型"层面）

1. **包注册的菜单不参与中文本地化** → `创建 → 2D` 下面中英混排（"瓦片地图 → **矩形**"是中文，"**Sprites**"是英文），不是装坏了
2. **资产类菜单在「项目」窗口右键，不在「层级」窗口** —— 层级右键是 **GameObject 菜单**（只给场景物体）；判据：菜单里有"设置默认父级 / 在场景中查找引用"就是层级菜单
3. **Unity 6.3 没有单独的"瓦片 (Tile)"菜单项**（在 `2d.sprite` / `2d.tilemap` / `2d.tilemap.extras` 三个包 + 两个编辑器程序集里搜 `2D/Tiles/Tile` **全 0 命中**）→ 正确路径是**把精灵拖进调色板**（`TileDragAndDrop` 会自动 `CreateAsset` 生成 `.asset`）
   - ⭐ **落点规律**：拖入生成的瓦片落在**「项目窗口当前打开的文件夹」**（源码 `GetDefaultTileAssetDirectoryPath` → `ProjectBrowser.GetActiveFolderPath()`）→ **先进目标文件夹再拖**
4. **2D 物理材质 ≠ 3D 物理材质**：`.physicsMaterial2D`（`PhysicsMaterial2D`）／ `.physicMaterial`（Unity 6 里叫 `PhysicsMaterial`）→ **类型不匹配时 Unity 拒绝拖入**（"响亮地失败"，与 `CompareTag` 抛异常同族）；**换碰撞体会清空材质槽**，别忘了挂回去
