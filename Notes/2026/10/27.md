## 一、算法：`74` 搜索二维矩阵（二分线第 5 题）

### 1. 单调性凭什么成立

| 性质 | 缺了会怎样 |
|---|---|
| ① 每行升序 | 行内没法二分 |
| ② **下一行首 > 上一行末**（严格跨接） | 矩阵**按行读出来不再是一条升序数组** ⇒ "当一维数组二分"这个前提塌掉 |

⭐ 判据：**先回答"我这套单调性靠哪条性质立的"，再动笔** —— 性质换了，模板必须跟着换。

### 2. 定行的三种写法（本题选了第三种）

| 写法 | 要点 |
|---|---|
| 甲 · 展平成一维 | 区间 `[0, m·n−1]`，比较 `matrix[mid/n][mid%n]`；**分母是列数不是行数** |
| 乙 · 定行再行内二分 | 找"最后一个 `首 ≤ target` 的行"，是**边界问题**不是等值查找；**可能一行都定不出来** |
| **丙 · 按行值域二分（本题）** | 直接问 `target ∈ [matrix[mid][0], matrix[mid][cols]]`，不在就按大小上下走 |

丙成立的理由：**② 保证各行值域互不重叠且整体有序** ⇒ "值域包含"本身就是可二分的单调量。
⚠️ 边界：`240`（行内升序 + 列内升序，**行间不接**）里这段定行**整段失效**，只能走上/右下角那套。

### 3. 坐标换算的坑

`r = k / n`、`c = k % n` —— **分母是列数**。方阵会让写反的人**全绿**，所以用例专设 `2×3` 与 `3×2`。
⭐ 症状指纹：**只有非方阵错 ⇒ 别怀疑二分逻辑，去查分母**。

### 4. 两处自查（记下来，以后写"两次二分"先照这两条）

1. `rows` / `cols` 存的是**最大下标**，不是行数/列数 —— 命名骗人（换成路线甲时最容易踩）
2. 「哨兵 + 出循环再判」与「命中即返回」是两种风格，**混用会多养状态**（本例第二段的 `col` 实质只等于一个 `bool`）

### 5. 判题器

| 部件 | 内容 |
|---|---|
| 手写用例 | **24 组**：形状边界（1×1 / 1×n / n×1）· 跨行接缝（上一行末 / 下一行首 / 行间空隙）· 非方阵 · 负数 · 100×100 四端 |
| **前提自检** | 每组建模后先验 ①② 是否真成立，破了就标"这组不算数"（免得在**不存在的题**上判分） |
| **全量对账** | 7 种形状 × 每种 20 张随机严格递增矩阵，`[最小−1, 最大+1]` 逐个整数比暴力扫 |
| 结果 | **23/23 全绿** ｜ 对账 **11034 次查询 0 处不符** ｜ Bench **2.3 ms**（100×100 查 2 万次） |

复杂度：`O(log m + log n)` / `O(1)`（与 `O(log(m·n))` 同阶）。**网页 AC**。

## 三、计基随行（10 分钟）：蒙皮 / 骨骼 / 肌肉空间

| 概念 | 一句话 |
|---|---|
| **蒙皮** | 骨骼只管动，顶点被**若干骨骼按权重加权平均**拉着走（权重和 = 1） |
| **骨骼** | Unity 里就是**普通 `Transform`**；骨架 = 父子 Transform 链 |
| **Humanoid / Avatar** | **不是动画格式，是一层翻译**：模型骨骼 → 标准槽位 |
| ⭐ **肌肉空间** | 动画存的是**相对姿势**（旋转归一化成 −1..1 的力度），播放时按**目标骨骼长度**反算 |

⭐ 判据：**同一条 Humanoid 动画播在不同身高模型上不穿模** = 重定向生效；某个槽位红叉 ⇒ 那个部位**静默不动**（不报错）。
📌 与 Root Motion 的接缝：**位移是剪辑里唯一的世界空间曲线，姿势是相对量** ⇒ 这就是"Root Motion 只夺位移、不夺姿势"的数据层根据。
