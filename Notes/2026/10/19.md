## 一、算法：`107` 二叉树的层序遍历 II

| 项 | 内容 |
|---|---|
| 题眼 | **`102` 的镜像题**：BFS 装备一字不差（`times = q.Count` 取在 `for` **之前**），唯一新决定 = **"层间颠倒"装在哪一步** |
| 路线 | 走 **②：一路 `Add`，最后 `result.Reverse()` 一次** ⇒ O(L) 次引用搬移 |
| 对照 | 路线① 每层 `Insert(0, …)` ⇒ 共搬 `L(L−1)/2` ≈ **O(L²)**，比 ② 多一个因子 L（L ≤ h ≤ n） |
| 坑 | ⚠️ `List<T>.Reverse()` **就地改、返回 `void`** ⇒ 必须确认翻的是「装层的大列表」，不是「某一层的元素列表」（翻错 = 当场退化成 103 的锯齿形） |
| 复杂度 | 时间 **O(n)**；空间 **O(w)**（w = 最宽层宽度：斜链 1、满树 ≈ n/2） |

### ⭐ 用例设计判据（今天最值钱的一条）

**两种错法的「最小可抓形状」不一样，不能一句话打包：**

| 错法 | 最小可抓形状 | 斜链上能抓到吗 |
|---|---|---|
| A 忘了翻 | **层数 ≥ 2** | ✅ 能（4 层斜链期望 `[[4],[3],[2],[1]]`，错解给正序） |
| B 层内也反 | **某层 ≥ 2 个节点** | ❌ **永远抓不到** —— 长度 1 的 `Reverse()` 是恒等变换 |
| 两种都抓不到 | 空树 / 单节点（只有一层 + 宽度 1） | — |

⇒ 收口一句：**"反转"这类操作在长度 1 的集合上是恒等变换 ⇒ 想抓它，用例里必须有长度 ≥ 2 的集合。**

## 二、C#：async 实战

### ① 并发账（三组实测）

| 场景 | 期望 | 实测 |
|---|---|---|
| 串行 `await Task.Delay`（5×300 ms） | ≈ 1500 | **1545 ms** |
| 并发 `Task.Delay`（同 5 条） | ≈ 300 | **314 ms** |
| 并发 `Task.Run(Thread.Sleep)`（同 5 条） | ≈ 300 | **339 ms** |
| 线程池线程数 | — | **6** |

⭐ **314 与 339 差 25 ms，但一个没借人、一个借了 5 条** —— 光看耗时分不出这两者，**必须看线程**。
⇒ 判据：**`Task.Delay` 等在内核（不占线程），`Thread.Sleep` 按住线程（必须 `Task.Run` 才并发得起来）**。

三条实现约束（绕开就量不出东西）：① 计时器 `StartNew()` 拿在第一个 `await` **之前**；② `Task.Delay` 版**不许**用 `Task.Run` 包；③ `Thread.Sleep` 版**必须**包在 `Task.Run` 里。

### ② 异步加载：进度 + 异常

- 4 档 `IProgress<int>`（25/50/75/100），每档之间 `await Task.Delay(50)` 冒充 IO
- `name` 含 `"bad"` ⇒ **推进到 50 之后**抛 `InvalidOperationException`
- ✅ **异常在 `await` 那一行被接住**（不是调用那一行）
- `await Task.WhenAll(t1, t2)` **只抛第一个**；两个任务内部各自都有 1 个异常 ⇒ 想全要必须读每个 task 的 `Exception`

### ③ `IProgress<T>` / `Progress<T>`（细节归纳）

| 事实 | 说明 |
|---|---|
| 接口只有**一个**成员 | `void Report(T value)` |
| `Progress<T>` **构造时**捕获 `SynchronizationContext` | 控制台为 `null` ⇒ 回调落**线程池**（实测线程 **7/7/7/8**，不是 main 的 1） |
| `Report` 是**显式接口实现** | 变量声明成 `Progress<T>` 会**编译不过**，必须写成 `IProgress<T>` |
| `Report` 返回 ≠ 回调执行完 | 异步投递 ⇒ 判题器要 `await Task.Delay(80)` 才数得够 4 次 |
| 为什么不用 `Action<int>` 直接传回调 | `Action<int>` **没有任何封送能力**；`Progress<T>` 的价值就是"自带回家地址" |

### ④ 技能冷却：两条路对照

| | A · async（事件式） | B · 时间戳（状态式） |
|---|---|---|
| 核心 | 上锁 → try 跑效果 → catch **退锁 + rethrow** → **fire-and-forget** 启动冷却 → `return true` | `now = Stopwatch.GetTimestamp()` → 没到 `_nextTick` 就 false → 推进 `_nextTick` → 跑效果 |
| 实测 | 首次使用 **1 ms**（不阻塞） | 行为一致 |
| 代价 | 状态机 + 定时器 | 一次比较 + 一次乘法 |

- ⚠️ **绝不能 `await` 整个冷却**：调用方被拖住 400 ms，而且等它返回时冷却早结束 ⇒ "冷却中再来"会错判
- ⚠️ 冷却时长换算必须写 `_cdMs / 1000.0 * Stopwatch.Frequency`；写成 `_cdMs / 1000`（整数除法）⇒ 400 ms 变 **0 tick**
- ⭐ **收口判据**：**"现在能不能用"是【持续条件】⇒ 状态式更贴合；"冷却结束那一刻要办事"才是【一次性响应】⇒ 才用事件式。** 与 10-17 Unity 那条「一次性响应用事件、持续条件读状态」是**同一条**。

### ⑤ 顺带钉死的三条

1. **`async` 与 `Task<T>` 是两件独立的事**：`async` 管"能不能中途离开"，`Task<T>` 管"离开时交一张写着 T 的票"。实测两条编译错误 —— 想 `await` 却不写 `async` ⇒ **CS4032**；写了 `async` 却返回 `bool` ⇒ **CS1983**（async 的返回类型只能是 `void` / `Task` / `Task<T>` 家族）。
2. **`_ = FooAsync();` = fire-and-forget**：抑制 **CS4014**（"此调用未等待"），同时把"疑似漏写"变成"明确意图"。代价 = 里面抛异常**没人接** ⇒ 只放不会失败的事。
3. **`Action<T>` / `Func<T>`**：`Func<Task>` 才能装"要等的活"；`Action` 只能装同步的。

### ① 对象池的父子归置

- `Instantiate(prefab, poolRoot)`：**出生就进回收站**，否则新实例会在场景根级冒一帧
- `OnGet`：`SetParent(obstacleRoot, worldPositionStays: true)` —— 改归属、不改世界位置
- `OnRelease`：`SetParent(poolRoot, …)` 再 `SetActive(false)`
- ⚠️ 父物体**缩放必须 (1,1,1)、不许旋转**（缩放是乘法传播，旋转会带着子物体歪）

### ② 金币 = 同一个池只换纵坐标

- `CoinSpawner` 与 `ObstacleSpawner` 的 `spawnCount / spawnStartZ / spawnSpacing` 填**同一组数** ⇒ 金币正好落在每个障碍的正上方
- 表现：绕**世界 Y** 自转 + 正弦上下浮动（`rotateSpeed` / `floatAmplitude` / `floatSpeed` 都在检查器里）
- ⭐ **与池配合的唯一陷阱**：`Get` 的顺序是 `SetActive(true)`（触发 `OnEnable`）→ **然后**才设 `position`。若在 `OnEnable` 记基准位置，记到的是**上一轮的旧位置**，浮动会围着错误高度跳 ⇒ 改成**第一帧 `Update` 懒初始化**，`OnDisable` 清标记。

### ③ 门卫：没有 Player 层怎么办

本工程的层表里**没有 `Player` 层**（只有 `Default / TransparentFX / Ignore Raycast / Water / UI / Ground`）。照抄"层门卫"⇒ 金币**永远吃不到，且控制台一声不响**。
⇒ 改成 `other.GetComponent<PlayerController>() != null`。判据：**触发器回调只在"真吃到"时触发一次**，省那一次 `GetComponent` 无意义；**"不依赖没建好的东西"更重要**。

### ④ ⚠️ 补上一行一直缺的代码

`GameManager` 里 `OnGameOver` 事件**声明了、但从来没人 `Invoke`** ⇒ 所有订阅者**永远收不到**。
症状极其隐蔽：**存档文件从不出现，控制台一声不响**。
修法就是一行 `OnGameOver?.Invoke();`，且顺序固定：**先上锁 → 再改状态（`timeScale = 0`）→ 最后播副作用（广播）**。

### ⑤ 结束之后：三件必须做的事

| 事 | 做法 | 判据 |
|---|---|---|
| **世界停住** | `Time.timeScale = 0f` | "停手（不再写速度）"治不了惯性滑行 —— 物理引擎照跑 |
| **面板渐入** | `CanvasGroup.alpha` 从 0 涨到 1，用 **`unscaledDeltaTime`** | `timeScale = 0` 时 `Time.deltaTime` **恒等于 0** ⇒ 用它会永远淡不进来 |
| **交还鼠标** | `Cursor.lockState = None` + `Cursor.visible = true` | 锁写在 `CameraFollow.Start`，解开也归它 —— **谁加锁谁解锁**；忘了就点不到 RESTART（编辑器里按 `Esc` 会自动解锁，容易把这个问题掩盖掉） |
